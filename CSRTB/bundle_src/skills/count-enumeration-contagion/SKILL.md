# count-enumeration-contagion — recount the enumeration before you state its count

## The rule (load-bearing atom)
WHEN about to state, relay, or quote a COUNT that summarizes an enumeration ⇒ RECOUNT the enumeration FIRST, before emitting the number. On any count-vs-enumeration mismatch the ENUMERATION outranks the count, and the underlying itemized record outranks both — correct toward the more itemized source. State no "N" or "N of M" without NAMING the population its denominator ranges over. WHY: a summary count silently drifts from its own list (a miscounted member, or a denominator borrowed from the wrong population); the drifted number then PROPAGATES because each downstream author copies the headline without recounting — so an unrecounted relay spreads the error while feeling like faithful quoting.

## The failure class (what this prevents)
- **count-vs-enumeration contagion**: a summary compression states a COUNT that disagrees with its own — or its source's — ENUMERATION of the items being counted; the wrong count then PROPAGATES as downstream authors and relayers copy the headline number without re-tallying. It is CONTAGION, not a single error: one compression can seed many documents.
- **denominator-shift** (sub-mechanism a): two candidate POPULATIONS are in play (e.g. a labeled subset vs the full set of flagged items) and the compression silently takes the COUNT from one and the DENOMINATOR from the other, so the emitted "N of M" names no real pairing. Why it hides: each of N and M is individually a true number from the record — only their PAIRING is fabricated, so neither half looks wrong in isolation.
- **member-miscount** (sub-mechanism b): a single list MEMBER is double-counted (or dropped), so the total over- (or under-) states the enumeration by one or more. Why it hides: the miscounted member is usually a real, correctly-named item — merely tallied twice (once as itself, once under a second description), which reads as thoroughness, not as error.
- **RANK — which source wins a mismatch**: itemized-record ≻ enumeration ≻ summary-count. The count is the LEAST authoritative artifact in the chain — derived, lossy, authored once; the items are the ground truth. Resolve every mismatch toward the more itemized source.
- **Why it is sticky**: relaying a trusted source's OWN headline number FEELS like faithful quoting, so no alarm fires in the relayer — quoting-verbatim and copying-an-error are the same motion here. Faithful relay transfers the error along with the number; trust transfers the error, not the truth.

## Origin (two same-week specimens, stated generically)
- **Specimen i — DENOMINATOR SHIFT** (caught late, after propagating to four docs): a classification record's OWN summary section compressed a two-population measurement into the single ratio "5 of 9". The record's detailed sections carried two DISTINCT correct pairings: 4 of 9 for the narrower population (items of one labeled kind that a remediation pass had authored to satisfy a prior instruction), and 5 of 10 for the broader population (all flagged items, including one item of a different kind that fell outside the labeled subset). "5 of 9" matches NEITHER — it borrows the count 5 from the ten-item population and the denominator 9 from the nine-item one. The record's detail was correct throughout; only its own summary conflated the two — which is exactly what let the summary read as authoritative. The wrong ratio then propagated VERBATIM into four downstream documents before an independent claim-vs-record review recounted from the detailed sections and caught it. Fix applied: correct to a named pairing — "4 of the 9 narrower-population items, all four directive-satisfying" OR "5 of the 10 flagged items, four of them directive-satisfying" — and annotate the stale summary in-band.
- **Specimen ii — MEMBER MISCOUNT** (caught at relay by a gate): an audit summary asserted a total of "9" immediately beside its OWN enumeration, which listed 8 distinct items — one member already in the list was double-counted (tallied once as itself, once as a separate "core statement" of the same item). A coordinator relaying the audit forwarded the "9" without recounting; an emit-time verification gate caught the relay. Correct total by tally: 8. Same class as specimen i: a count-vs-enumeration mismatch sitting inside a summary compression.

## Tells (output-detectable — any one fires ⇒ run the recount)
1. **count-from-summary**: you are about to write or relay an "N" or "N of M" whose source is a SUMMARY line, not your own tally of the underlying items ⇒ you have not counted yet; count before emitting.
2. **untallied-adjacent-enumeration**: a count sits directly beside an enumeration (a list, a table, a set of ids) that you have NOT tallied this pass ⇒ tally it; the adjacency is the cheapest possible check and the one most often skipped.
3. **ambiguous-M**: the M in "N of M" could name ≥2 populations (a subset vs its superset, labeled vs all, kept vs flagged) ⇒ denominator-shift risk; name which population M ranges over, explicitly.
4. **boundary-crossing**: the count appears to cross a category boundary — a subset figure paired with a superset denominator, or the reverse ⇒ the pairing is likely fabricated; re-derive both halves from the SAME population.
5. **same-number-many-docs**: the same number appears in multiple downstream documents that all trace to ONE upstream source ⇒ contagion signature; recount at the source, then sweep the copies (step 4 below), not the single instance in front of you.

## The recount-and-sweep (run the moment a tell fires)
1. **LOCATE** the enumeration the count summarizes — and if an itemized record sits beneath the enumeration, locate that too (it outranks both).
2. **COUNT** it — tally the actual items/rows; do not re-read the summary's own number back to yourself.
3. **ON MISMATCH**: correct the count toward the enumeration (or the itemized record); NAME the population ("N of M <kind> items"); and annotate the stale count IN-BAND, beside where it stands — PRESERVE the original figure and attach an adjacent antidote (e.g. a prefixed "[COUNT CORRECTED <date>: enumeration = K]"), so any later retrieval of the stale line meets its correction in the same read. Why preserve-plus-antidote: deleting the old number breaks the trail; leaving it bare re-seeds the contagion; the antidote beside it does both jobs at once.
4. **CONTAGION SWEEP**: search EVERY downstream document for the wrong number and fix the CLASS, not the single instance in front of you — the number that reached you reached its siblings too. Fixing only the copy you happened to see leaves the rest live, and a half-corrected document set is worse than an uncorrected one (some readers now trust the wrong number more).
5. **AT AUTHORING TIME**: derive any summary count mechanically FROM the enumeration (count the rows) rather than typing it from memory or from a prior draft — a count written from memory is an unverified claim the instant it lands.

## On Claude Science (substrate note — the mechanism is platform-neutral; the carriers are named)
Counting an enumeration is platform-agnostic, but name where the two defensive layers the specimens needed live on this runtime. The "downstream documents" the contagion sweep (step 4) must reach are ARTIFACTS + durable MEMORY rows — and memory AUTO-RECALLS, so a wrong count lodged in a memory row re-seeds every future session that reads it: recount BEFORE you write a count into memory, and keep ONE canonical memory row per figure (supersede in place, never append a near-duplicate). The independent claim-vs-record review (specimen i) and the emit-time gate (specimen ii) map to a `verification-loop` / adversarial-reviewer pass and the `countermeasure-audit` / reviewer disciplines. The in-band antidote (step 3) is the same write-time neutralization the `provenance-over-description` and durable-doc-currency skills apply to a stale claim.

## Caveat (no single layer suffices)
In BOTH specimens one defensive layer alone was insufficient — the catches came from an independent claim-vs-record REVIEW pass (specimen i) and an emit-time verification GATE (specimen ii) respectively, each downstream of the author who first compressed the count. A relayed count needs its OWN recount even when the source is trusted and even when the relay is verbatim; trust and faithfulness both transfer the error, not the truth. LIMIT: this rule REDUCES the failure only when loaded and only when a tell actually fires — it does not replace the review/gate layer; it is the author-side layer that should fire before them.

INVARIANT: a count is a lossy claim ABOUT an enumeration, never a substitute for it — recount before you state, relay, or quote one; prefer the more itemized source on any mismatch; name the population the denominator ranges over; and sweep the class when a number has already spread.
