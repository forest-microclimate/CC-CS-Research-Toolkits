# ─── §1 WHAT THIS ANSWERS ──────────────────────────────────────────────────
Q.three: this document answers three questions a user or maintainer hits in the moment. (1) A gate just refused something you did — WHAT refused it, and why does it exist? (2) You are adding a check — WHICH level does it belong at, and what does that level owe you? (3) You are asked whether the toolkit's assurances actually work — WHAT is measured, and what is merely built?
FACT.shape: the toolkit's assurances are not one mechanism. They are FIVE LEVELS, each doing a job the neighbouring levels cannot do: **RECORD** (facts survive) → **CONVENTION** (decisions have named shapes) → **ADVISE** (misses get named, never blocked) → **ENFORCE** (a silent omission becomes impossible) → **MEASURE** (efficacy is a number, never an assertion).
READ.order: §2 the law the whole ladder rests on · §3 the five levels · §4 what each level buys that its neighbours cannot · §5 the honest limit · §6 one compact entry per shipped mechanism · §7 the control surface · §8 adding a level of your own.

# ─── §2 THE LAW BENEATH: STRUCTURAL OVER DISCIPLINARY ──────────────────────
LAW.structural_over_disciplinary: WHEN choosing among candidate assurances ⇒ prefer a MECHANISM that fires at the decision moment over an EXHORTATION that has to be remembered. An instruction in a prompt fires only if the prompt was loaded AND the model chose to comply; a hook on the tool call fires regardless of both.
WHY.not-a-preference: this is a conclusion from recorded defects, not a style choice. Three shipped mechanisms carry their own origin in their headers.
  EX.dispatch-hole: a model ban held at BUILD time (a barred id cannot ship in the payload) and at PLAN time (a plan cannot declare one) — and a launch typed in the moment reached the barred model with no check at all, because neither gate sat on the dispatch path. The dispatch guard exists to close exactly that hole and nothing else.
  EX.declared-not-done: a routing mandate written into the planner's prompt produced a plan declaring six delegation tracks, four of which the lead then ran itself. The plan-approval gate lints the routing block at the tool call, so the plan is corrected before the user ever sees it.
  EX.docs-not-loaded: the launch conventions for a verified frontier-tier child kept failing to reach sessions that never loaded the documents stating them. The dispatch gate enforces the launch SHAPE, so the convention arrives whether or not the doctrine did.
COROLLARY.default_inversion: WHEN an action's costs are asymmetric ⇒ default toward the cheap-to-reverse side and require an explicit token for the expensive side. Every gate here fails OPEN on its own internal error (exit 0 always, the refusal riding in structured output, the error logged) — a broken guard must never wedge a session, and a silent fail-open is itself the bug, so the fail-open is logged.
LIMIT.law: the law says prefer a mechanism; it does not say a mechanism can do everything. §5 states what no gate on this ladder can do.

# ─── §3 THE FIVE LEVELS ────────────────────────────────────────────────────
LEVEL-1.RECORD (facts survive): nothing above this level means anything if the facts do not outlive the session that produced them.
  - APPEND-ONLY LEDGERS, four, each readable by a worker with no prior context: the CHANGE ledger (one dated row per change; past rows are never edited) · the EFFICACY ledger (one row per check, carrying its status and the measurement that justifies it) · the CODE inventory (every script, so the next worker USES or ADAPTS rather than rebuilding) · the PLAN ledger (which plan is active, parked, or finished).
  - RECEIPTS DISCIPLINE: state a current fact only from a FRESH read or measurement made for that claim. Recollection cannot be audited; a command's output can.
  - SERVING STAMPS: the model identity of a run is read from the API response's own per-call `model` field in that run's transcript — the only record downstream of what actually ran. Every other signal (a launch argument, a resolution, a UI header, the run's own testimony) records intent or belief.
  - COMPLETION TELEMETRY: one structured row per subagent completion, CLEAN COMPLETIONS INCLUDED, because a rate needs a denominator. Each row carries the hook build that wrote it, so a later analyst can separate pre-fix from post-fix populations instead of pooling them.
LEVEL-2.CONVENTION (decisions have named shapes): a decision with no named shape cannot be checked by anything — not by a hook, not by a reviewer, not by the person who made it.
  - THE PROJECT CONTRACT: a project-level `CLAUDE.md` stating the supervisory workflow, the folder contract, and the standing rules, installed into the project root rather than remembered.
  - THE SIX-ELEMENT BRIEF: assignment (with a checkable done-condition) · read-paths (self-service — the child reads the sources itself, never only a summary) · write-path (in-workspace, for ALL products, code included) · report cap (a line budget plus the receipts each claim must quote) · the stop-when-stuck rule verbatim · the scope rule verbatim. An EMPTY element means not ready to launch. The fill-in form ships at `dev/briefs/_TEMPLATE.md`.
  - ROUTING BLOCKS WITH OWNERS: a plan's delegation block names, per track, the executor AND an owner that says more than the executor tag — the persona or skill assignment — or carries the explicit "no specialist fits" fallback.
  - THE ROLE ASSIGNMENT: a brief's `ROLE:` line names which persona the child runs as, and the brief points at that persona's file.
  - PERSONA AND SKILL DELIVERY BY READ-POINTER: a brief NAMES the persona file or `SKILL.md` path and the child reads it itself. Two things follow — the child can audit what it was given, and (for a frontier-tier child) those opening reads double as the warmup that makes serving certifiable early.
LEVEL-3.ADVISE (misses get named, never blocked): the level for things that are usually an oversight and occasionally a considered choice — where refusing would be wrong more often than it would be right.
  - THE BRIEF-SLOT ADVISORY names any unfilled brief slot at launch time and never refuses the launch.
  - THE COMPLETION-TELEMETRY NUDGE puts one advisory note in front of the model when a finishing child's own final message scans at severity 2 or worse.
  - THE WATCHDOG SCAFFOLD prints, after a frontier-tier launch returns, the ready-to-run certification command with the child's transcript path already substituted, plus the exit-code legend — so the next action requires zero recall.
  - PLAN-STATE RE-INJECTION restores the active plan's name, its snapshot path, and the resume protocol at each session boundary (startup, resume, post-compaction), for roughly a hundred tokens per boundary EVENT rather than a per-prompt tax.
LEVEL-4.ENFORCE (a silent omission becomes impossible): the level for omissions that are silent by nature — the ones nobody notices at the time, which is precisely why advice does not reach them.
  - THE DISPATCH DENY-GATE refuses a frontier-tier launch that names no brief and opens with no warmup, names a brief that is absent or unreadable, or names a brief missing its `ROLE:` line, its persona pointer, or (frontier tier) its warmup slot.
  - THE PLAN-APPROVAL GATE refuses the plan-approval tool call when the plan's routing block is missing or malformed, including owner-explicitness and multi-stage enumeration, so the plan is fixed BEFORE the user is asked to approve it.
  - THE TURN-VERDICT BLOCK stops a turn ONCE when it launched a certified-route child and names no serving certification, printing the ready-to-run certification command.
  - ONE-SHOT BY CONSTRUCTION: a turn-level block fires at most once per stop sequence, guarded by the harness's own already-blocked flag. A gate that could fire twice is a loop, not a gate.
LEVEL-5.MEASURE (efficacy is a number, never an assertion): the level that decides whether any of the four below it actually worked.
  - LIVE CERTIFICATION reads a still-running child's first serving stamps and returns a verdict by about the fifth call.
  - THE POST-HOC AUDIT catalogs every run's launch argument vs resolved model vs SERVED model with a per-run verdict and a gate-able exit code.
  - COMPLETION TELEMETRY (Level 1's rows) becomes a RATE here: rows carry denominators and build tags, so "did the fix work" is answerable by comparing populations rather than by assertion.
  - THE ADHERENCE SCORECARD scores a session's transcripts on five greppable dimensions as n/N (n = compliant, N = opportunities OBSERVED), and dates each OPPORTUNITY by the transcript record that carries it, so an interrupted time-series across a gate's ship instant is interpretable rather than smeared by sessions that straddle it. It MEASURES; it never blocks and never edits. NOTE.shipped: the workflow kit INSTALLS it at `<project>/dev/tools/adherence_scorecard.py`, with its fixture guard beside it — so the METHOD by which the grades below were earned is one you re-run on your OWN sessions, not merely a citation. Its lineage classification derives from YOUR project root, so your sessions score as yours.
  - THE EFFICACY-LEDGER DISCIPLINE fixes the vocabulary every grade in §6 uses, five values: `attempted-untested` (built, not yet measured — the status of anything new, by default) · `fixture-measured` (exercised against labeled fixtures or test cases; behaves as specified ON THOSE CASES) · `measured-working` (measured before/after on real outcomes, stated WITH the numbers) · `measured-regressed` (same evidence standard, opposite result) · `retired`. No check moves past `attempted-untested` without a cited measurement, and "I built it" is never a measurement.

# ─── §4 WHY FIVE — WHAT EACH LEVEL BUYS THAT ITS NEIGHBOURS CANNOT ─────────
BUY.record: without it every other level is unauditable. A gate that fires and leaves no row cannot be told from a gate that never fired.
BUY.convention: without a named shape there is nothing to check. Levels 3 and 4 do not check goodness; they check CONFORMANCE to a shape Level 2 defined, which is why every enforcement below points at a convention above.
BUY.advise: it covers the large class where refusal would be wrong. An advisory that names a miss costs a line of context; a refusal that is wrong costs a retry, a workaround, and eventually the operator switching the whole layer off — which is the real failure mode of over-enforcement.
BUY.enforce: advice reaches only an agent that reads it. The recorded failures at §2 are all cases where the advice existed and did not arrive: the ban was written down, the routing mandate was in the prompt, the launch convention was documented. Enforcement is what fires when the doctrine did not load.
BUY.measure: without it the other four are a story. `attempted-untested` is the default for a reason — a mechanism's existence is evidence about the author's intent, never about its effect.
RULE.pick_the_level: WHEN adding a check ⇒ choose the level by ONE question — what happens if the target behaviour is absent? Recoverable and often deliberate ⇒ ADVISE. Silent and rarely deliberate ⇒ ENFORCE. Not yet known ⇒ ADVISE first, MEASURE the rate, then promote. TELL: you are about to add an enforcement whose false-positive rate you cannot state ⇒ ship it as advice and measure it.

# ─── §5 THE HONEST LIMIT (stated as prominently as the powers) ─────────────
LIMIT.made_recorded_wellformed: every gate on this ladder forces a decision to be **MADE**, **RECORDED**, and **WELL-FORMED**. None of them forces it to be **WISE**. The owner-completeness and multi-stage checks are the clearest case: they are MINIMUM-EXPLICITNESS checks, and a routing block naming the wrong specialist for every track passes all of them.
LIMIT.form_not_truth: the same boundary in general — these mechanisms check FORM and IDENTITY, not content-truth. A well-formed false claim passes. A brief with all six slots filled with nonsense passes. A certified child can be certified as the right model and still be wrong about the work.
RESIDUAL.two_stage: the judgment residual is not left unowned; it belongs to TWO-STAGE DETECTION. Every round that outputs a product a standard covers only partly runs: (1) the automated detectors scan and disposition FIRST, results recorded; (2) the standard's OWNER — the user by default, where no style or standard document exists yet — sweeps the SAME output for what stage 1 missed. Output is never called clean on stage-1 evidence alone.
RESIDUAL.misses_become_fixtures: each stage-2 miss becomes (a) a labeled fixture pairing the flagged text with the corrected text, (b) a row in the change ledger, and (c) a routing decision — to the next detector build, or to the judgment checklist when no detector shape fits. Per-round residual counts accumulate, and the RATE-DROP TREND across rounds is the real efficacy measurement; a single round's count is a baseline, not a verdict.
LIMIT.silenceable: every mechanism here can be switched off (§7). That is deliberate — an operator who sets the switch has made the layer inert on purpose, and a gate that ignored the switch would be a surprise. The consequence: these gates are a floor for a cooperating operator, never a control over a determined one.
LIMIT.regime: a measurement is a statement about the conditions it was taken under. Where the measured thing is served remotely, its rates can drift on the scale of hours without any local change, so certification AT LAUNCH — not configuration, and not a rate measured yesterday — carries the guarantee. `MODEL_SUBSTITUTION_AND_VERIFIED_LAUNCH.machine.md` holds that case in full.

# ─── §6 MECHANISM ENTRIES (nuts and bolts) ────────────────────────────────
KEY: FILE = the path an adopter has after install. `<project>/` = the project root you installed the workflow kit into; `~/.claude/` = the global toolkit install. EVENT = the harness event and matcher it registers on. GRADE = the efficacy-ledger status, copied.
COMMON CONTRACT (all hook entries): input is ONE JSON object on stdin. EXIT is **0 always** — a refusal rides in the structured stdout, never in the exit code, because the model needs the reason in order to retry, and that retry is the point. Any internal error (no interpreter, unparseable input, an unexpected shape) is INDETERMINATE ⇒ FAIL OPEN and log. All are read-only apart from their own log lines.
COMMON TEST (the adopter-reachable smoke, and the reason it is valid): every hook here is a pure stdin-JSON reader, so replaying one crafted payload IS the real firing path — nothing about a live session changes what the script reads. Form: `printf '<payload>' | bash <hook path>`, then read stdout (empty = silent pass, one JSON object = a decision) and stderr (advisory text). Worked example, a briefless frontier-tier launch, which must print a deny object:
  `printf '{"tool_name":"Agent","cwd":"/tmp/x","tool_input":{"subagent_type":"fable-executor","prompt":"do a thing"}}' | bash "<project>/.claude/hooks/fable-dispatch-gate.sh"`
  Then invert it: point the prompt at a compliant brief and confirm SILENCE. A gate you have only seen pass is not a gate you have tested — show it refusing the thing it exists to refuse, then show it passing what it must not refuse.
NOTE.regression-batteries: each hook names its own PER-HOOK regression battery in its header comment (`tests/test_<name>.sh`); those stay DEVELOPMENT-side and are not part of the release cut. The END-TO-END battery, however, SHIPS: `<project>/dev/tools/test_enforcement_e2e.sh` replays the whole violation set against the INSTALLED hook copies AND their `.claude/settings.json` registrations — the delivery layer, which a vendor tool-rename kills silently while every hook file stays perfectly correct. One command, exit 0 = every arm behaved. Arms needing a surface a given project may not have (the global toolkit install; a live plan under `plans/current_active/`) print SKIP, never FAIL — a false FAIL is how a check teaches its adopter to ignore it.

## 6.1 ADVISE
ENTRY.brief-advisory
  FILE `<project>/.claude/hooks/brief_gate.sh` · EVENT PreToolUse, matcher `Task|Agent`
  TRIGGER a subagent launch. The prompt or description naming a `dev/briefs/*.md` file is looked up; a substantive launch naming none gets a one-line note; a trivial launch (read-only searcher, short prompt, no write intent) passes in silence.
  YOU SEE injected context naming the unfilled slots — the six brief elements plus the `ROLE:` routing line, all advisory. It emits no permission decision at all: it advises, it does not deny.
  SILENCE `PLANNER_KIT_HOOKS=off` · GRADE `fixture-measured`
ENTRY.launch-scaffold
  FILE `<project>/.claude/hooks/fable-launch-scaffold.sh` · EVENT PostToolUse, matcher `Task|Agent`
  TRIGGER a certified-route or probe launch RETURNS and the response carries an `output_file:` path. No path ⇒ fully silent.
  YOU SEE on stderr, the ready-to-run certification command with the child's transcript path substituted, plus the legend: FAITHFUL(0) = certified, continue · SWAPPED@k(1) = relaunch or proceed knowingly and log it · UNDETERMINED(2) = investigate. Stdout stays empty — this hook decides nothing.
  SILENCE `PLANNER_KIT_HOOKS=off` · GRADE `fixture-measured`
ENTRY.plan-state-injector
  FILE `<project>/.claude/hooks/plan-state-inject.sh` · EVENT SessionStart, matchers `startup`, `resume`, `compact`
  TRIGGER a session boundary, with a `plans/PLAN_LEDGER.machine.md` row marked ACTIVE under the project dir. Multiple ACTIVE rows ⇒ the last is named plus a count of the rest. No ledger, no ACTIVE row, or any parse doubt ⇒ silent.
  YOU SEE about two lines: the active plan's name and snapshot path, then the one-line resume protocol including the verified-launch reminder. Stdin is drained and ignored; it writes NOTHING, not even a log — a session-boundary hook is a pure reader.
  SILENCE `PLANNER_KIT_HOOKS=off` · GRADE `fixture-measured`, with one live output receipt against a real ledger

## 6.2 ENFORCE
ENTRY.dispatch-deny-gate
  FILE `<project>/.claude/hooks/fable-dispatch-gate.sh` · EVENT PreToolUse, matcher `Task|Agent` · THE one deny-capable launch gate.
  TRIGGER a launch whose subagent type is one of the two certified executor routes, or whose model argument names the ceiling tier. Subagent types beginning `probe-` are allowlisted (probe cells are legitimately briefless by design); everything else passes silently.
  CHECKS three. (1) LAUNCH SHAPE — the prompt or description names a `dev/briefs/*.md` brief, OR the prompt opens with the warmup token; neither ⇒ DENY, and a NAMED brief that is absent or unreadable ⇒ DENY (a dangling brief pointer is a launch defect, not a parse error). (2) ROUTING EXPLICITNESS, when a brief resolves — the brief carries a `ROLE:` line AND, anywhere in the file, either a persona-file reference or the literal fallback phrase; missing ⇒ DENY. The scope is the WHOLE brief on purpose, because persona pointers legitimately ride the warmup slot rather than the ROLE line. (3) VERIFIED LAUNCH, ceiling tier only, when a brief resolves — the brief carries the warmup token; missing ⇒ DENY.
  YOU SEE a denial of the launch with a reason of at most four lines: the check that failed, the element that is missing, the fix, and the template path.
  SILENCE `CRT_MODE=off` or `CRT_MODE=observe` (an intervention hook: `on`, the default, is the only enforcing value) · GRADE `live-measured`
ENTRY.plan-approval-gate
  FILE `~/.claude/hooks/plan-routing-gate.sh` · EVENT PreToolUse, matcher `ExitPlanMode`
  TRIGGER the agent is about to present a plan for approval. Every routing fence AND the markdown table are linted, not just the first, so a compliant first block cannot shadow a violating second one.
  CHECKS the frozen routing-schema lint set, including: a declared delegation track must actually delegate (body text saying the lead runs it is caught) · barred model ALIASES are denied wherever they appear, because an alias re-resolves silently and is therefore never a sanctioned route · a raw model FIELD naming a restricted model is denied, while NAMING that model inside an executor, owner, task, or tradeoff field is allowed, so a plan that legitimately routes to a supervised executor can say so without the gate reading its own documentation as a violation · a supervised-executor track must carry its supervision marker, since the marker is what distinguishes a watched run from a routed-and-abandoned one · OWNER-COMPLETENESS: a delegation track's owner must say more than the executor tag, or carry the explicit fallback · MULTI-STAGE COMPLETENESS: a track declaring a cascade topology must enumerate at least two stages, and a plan routing more than one delegation track must carry a waves or ordering section.
  YOU SEE the approval call denied with the failing check named, so the plan is corrected before the user is asked to approve it.
  NOTE.extraction the current harness sends neither the plan text nor its path in the tool input, so the gate falls back to the newest plan file in the plans directory, accepted only when its modification time is within the last thirty minutes; any miss (no directory, no file, too old, unreadable) is a logged fail-open rather than a lint failure.
  SILENCE `CRT_MODE=off` / `observe` · GRADE `live-measured`
ENTRY.alias-dispatch-guard
  FILE `~/.claude/hooks/opus-dispatch-guard.sh` · EVENT PreToolUse, matcher `Task|Agent`
  TRIGGER a launch whose model argument is a bare restricted alias, alone or context-suffixed. Everything else — a named tier alias, a full model id, no model key at all — passes SILENTLY.
  WHY-ALIASES-ONLY an alias reads to a human like a tier choice while resolving at launch to whatever the launcher currently maps it to, and it re-resolves silently whenever that mapping changes. A full id is deliberately NOT denied here: the launch parameter accepts aliases only, so a full id is rejected upstream by the harness, and the sanctioned supervised route names an AGENT whose own frontmatter carries the pin, not a model.
  YOU SEE the launch denied with the structured reason.
  SILENCE `CRT_MODE=off` / `observe` · GRADE `fixture-measured` (matrices with no-guard red baselines; the code inventory additionally records live firing in the session it shipped)
ENTRY.turn-verdict-block
  FILE `<project>/.claude/hooks/collect_outcome_gate.sh` · EVENT Stop
  TRIGGER two layered checks over the segment AFTER the last genuine user message. (a) OUTCOME: the turn collected subagent results and the reply names none of the six collect outcomes. The "this turn saw subagent results" signal is read from the transcript by three independent tells, any one sufficient; no tell ⇒ silent, so the gate never fires on a turn it cannot read. (b) VERDICT: the same segment launched a certified-route child and carries NO certification token — a verdict word or a serving-stamp receipt line — searched in DECODED content text only, so a transcript record's own model field can never masquerade as a receipt and a user prompt (which the segment excludes) can never certify a child it merely mentions.
  YOU SEE one block with the request. A Stop hook has no advisory channel — blocking is the only way to put text in front of the model, and it costs one extra turn, which is why the trigger is narrow. On the verdict check the block names the ready-to-run certification command with the child transcript path substituted from the launch result.
  ONE-SHOT the harness's already-blocked flag covers BOTH checks: at most one block per stop sequence, never two.
  SILENCE `PLANNER_KIT_HOOKS=off` · GRADE outcome check `fixture-measured`; verdict check `fixture-measured`

## 6.3 MEASURE
ENTRY.live-certification
  FILE `<project>/.claude/skills/model-verification/fable_watchdog.py` (also installed globally with the toolkit's skills)
  RUN `python3 <path>/fable_watchdog.py <child-transcript> [--expect <model-id>] [--verdict-at 5] [--watch]`
  TRIGGER you, at or just after a launch. `--watch` polls a still-growing transcript, so it can be pointed at a RUNNING child.
  YOU SEE one verdict line, and the exit code IS the verdict: `0` FAITHFUL (the first `--verdict-at` stamps all equal `--expect`) · `1` SWAPPED@k (the first divergent stamp is call k, decided the moment a divergence is seen) · `2` UNDETERMINED (too few stamps yet, no assistant records, or unparseable — never a crash).
  PAIRS-WITH the warmup convention: the brief's persona and skill Read-pointers ARE the opening calls, so the transcript reaches a certifiable length through useful work rather than throwaway calls.
  GRADE `live-measured`
ENTRY.post-hoc-audit
  FILE `~/.claude/skills/model-verification/model_run_audit.py`
  RUN `python3 <path>/model_run_audit.py <project-dir | session.jsonl | session-dir> [--json|--tsv|--summary-only]`
  YOU SEE every run catalogued across its record layers — the raw launch argument, the harness's resolution, and the API's own SERVED stamp — with a per-run verdict of MATCH, MISMATCH, or UNKNOWN, plus totals by served model and the mismatch signature. EXIT `0` no mismatch · `1` at least one mismatch · `2` input or parse error. UNKNOWN never gates: a main-loop run carries no intent layer by construction.
  CAUTION a naive grep for `"model"` over a transcript that LAUNCHES children also matches each launch's model ARGUMENT and config echoes, mixing intent into what reads as a serving tally. The audit script separates the layers; the skill documents an accurate one-liner for when the script is unavailable.
  GRADE `fixture-measured` plus one live acceptance run
ENTRY.completion-telemetry
  FILE `~/.claude/hooks/subagent_qa_gate.sh` · EVENT SubagentStop
  TRIGGER a subagent finishes. It writes ONE structured row per completion — clean completions included — and puts an advisory nudge in front of the model only when the scan found something at severity 2 or worse.
  SCOPE the scanned text is the finishing CHILD's own final message, taken from the payload the harness supplies where present, and otherwise resolved through a documented ladder of narrowing fallbacks; each row RECORDS which resolution was used. This matters because the transcript path supplied on this event is the PARENT session's file, so "the last assistant message in the transcript" is usually the coordinator's text, not the child's — a measured source of false flags, each of which cost a turn to refute.
  VALUE-GATED CHECK one finding is not text-shaped: a certified route's serving stamp is compared against that route's shipped model promise, so a silent substitution becomes loud with zero operator discipline required.
  YOU SEE a row appended to the error-mode log; a nudge only above the severity threshold.
  GRADE child-scoped scan `fixture-measured` with a live signal on real rows; substitution flag `fixture-measured` — no real substitution has crossed it live yet.

# ─── §7 THE CONTROL SURFACE ───────────────────────────────────────────────
SWITCH.two: two switches, split by what a mechanism DOES rather than by which file it lives in.
  `PLANNER_KIT_HOOKS=off` silences the ADVISORY set — the brief advisory, the launch scaffold, the plan-state injector, and the turn-level Stop hook. These inject context or block a turn, so they must be silenceable.
  `CRT_MODE` gates the INTERVENTION set — the dispatch deny-gate, the plan-approval gate, and the alias guard. `on` (the default) enforces; `off` and `observe` BOTH silence. Set from the environment, or from the mode file the toolkit reads when the variable is unset.
RULE.switch_is_not_a_bypass: silencing is an operator act with a whole-layer effect, not a per-case escape. WHEN a gate refuses something legitimate ⇒ fix the SHAPE it is checking (fill the slot, name the owner, add the warmup) rather than switching the layer off — the refusal names the missing element and the template precisely so the fix is cheaper than the bypass.

# ─── §8 ADDING TO THE LADDER ──────────────────────────────────────────────
PROC.add: (1) name the failure the check exists to catch, and the RECORD that shows it happened — a check with no recorded failure behind it is a guess. (2) pick the level by §4's one question. (3) write the check so it fires at the DECISION MOMENT, fails open on its own error, and logs that fail-open. (4) show it RED before green: plant the exact fault it exists to stop and confirm it fires; an untested gate is an unverified claim one layer down. (5) register it at `attempted-untested` and say so where it ships. (6) promote it only on a cited measurement, and state the population that measurement covers.
GEN.transfers: the shape generalizes past this toolkit. Any system where an instruction can go unread by the party it binds meets the same split — a durable record, a named shape, a cheap advisory for recoverable misses, a hard gate for silent ones, and a measurement that decides whether the previous four earned their keep. What does NOT transfer is any particular rate: a rate belongs to the conditions it was measured under.
INVARIANT: the record outlives the session, the convention gives the check something to check, advice covers what refusal would get wrong, enforcement covers what advice cannot reach, and measurement decides whether any of it worked — while no gate anywhere on the ladder claims to make a decision WISE, which is why the human sweep at stage two is part of the architecture and not an admission about it.
