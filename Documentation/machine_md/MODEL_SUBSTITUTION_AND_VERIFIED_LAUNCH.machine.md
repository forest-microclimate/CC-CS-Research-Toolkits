# EVIDENCE BASE: every count below comes from SERVING-STAMP audits of Claude Code subagent transcripts taken 2026-08-02 → 2026-08-07 on Claude Code 2.1.220 through 2.1.223, one operator's machine, plus one restart-gated single-variable probe grid. Dates ride the numbers because the rates are time-conditioned (see RATE.regime-drift).

# ─── PREMISE (what happened) ───────────────────────────────────────────────
FACT.the-failure: a subagent request for `claude-fable-5` that is provably correct at EVERY client-side layer — the raw launch argument, the harness's resolution after precedence, the model shown in the interface — is silently SERVED `claude-opus-5` for some or all of its turns. No error, no warning, no notice in the transcript. The only record that reveals it is the API's own per-call model field.
FACT.founding-incident: this is the incident the toolkit's whole verification architecture was built around. It is why a model claim in this toolkit is settled by a transcript audit and never by a configuration file, an interface header, or the model's own account of itself.
SCOPE.narrow: the substitution affects ONLY `claude-fable-5`-targeted SUBAGENT requests. Every other model id was served faithfully in every measured era (31/31 across days; 100% of non-fable ids in the first measured population), and the MAIN conversation loop was never substituted.
FRAME.verification-not-prevention: prevention lives on the serving side and is out of user reach. What IS in reach is VERIFICATION — and because the swap point turned out to be deterministic and early, verification is cheap: a child's fate is observable by roughly its fifth call. Everything in §3 follows from that one property.

# ─── §1 THE FOUR-LAYER ANATOMY (which record answers "what ran?") ──────────
LAYER-1.raw-arg: the per-launch model ARGUMENT, recorded in the subagent's own metadata file (`agent-<id>.meta.json`, key `.model`; absent when the launch omitted it). An INPUT record. Says nothing about serving.
LAYER-2.resolved: the harness's LAUNCH-TIME RESOLUTION after the four-rank precedence, recorded on the launch row of the main transcript (`toolUseResult.resolvedModel`). It is the only field carrying the `[1m]` display suffix, and it is evidently what the interface header displays. This is INTENT, not serving — it diverged from the serving stamp in ~94% of fable-resolved launches during the measured incident.
LAYER-3.serving-stamp: the API RESPONSE's own `model` field, written per call by the serving side onto every assistant turn of the child transcript. THE ONE AUTHORITATIVE LAYER — the only record downstream of what actually answered.
LAYER-4.self-report: asking the child what it is running on. DISQUALIFIED as an instrument: wrong 3 of 5 times measured. A child assembles the answer from its own loaded context, so it echoes whatever its documents call the default — which is exactly the belief under test.
WITNESS.external: the account's usage-by-model metering is the one witness outside the transcript record. It cannot attribute tokens to a specific run, but a model carrying tokens you never requested is a serving-side fact no client-side layer can produce.
RULE.verification-law: a model claim is verified by the SERVING STAMP or it is not verified. Headers, configs, resolutions and the model's own testimony are statements of intent or belief — useful for diagnosing WHY a substitution happened, never evidence of WHAT ran. TELL: you are about to attribute a behavior (quality, error rate, speed, cost) to a named model without having read that run's stamps ⇒ read them first.
CHECK.one-line: `grep -oh '"model":"claude-[^"]*"' <child-transcript.jsonl> | sort | uniq -c`. The `claude-` prefix is load-bearing: on a transcript that LAUNCHES children, each launch's model ARGUMENT sits in the same field shape, so a bare alias in that field is never a serving stamp — the API stamps full ids only.

# ─── §2 THE MEASURED ANATOMY (the record, each item with its evidence shape) ─
SHAPE.two-modes: substitution arrives in exactly two shapes. DOA — the substituted model from call 1, characteristic of the earliest era and of full-tool children generally. DETERMINISTIC MID-RUN SWAP — exactly three faithful turns, then the substituted model for the rest, observed 7/7 across two days and in every swap of the 2026-08-06 campaign. EVIDENCE SHAPE: per-turn stamp sequences, read in order. CONSEQUENCE: the swap point is FIXED and EARLY, which is what makes early certification possible at all.
SPLIT.same-message: three identical-shape children of the same pinned agent, launched in ONE message within the same second, diverged — one faithful (×12), one swapped at call 4 (×3, then the substituted model ×8), one faithful (×19). Every client-side dimension is shared inside that trio: config files, environment, harness version, agent definition, launch instant. EVIDENCE SHAPE: three sibling transcripts from one launch message. CONSEQUENCE: the decision is PER-REQUEST and server-side; no client-side state can explain a split inside one message.
RATE.regime-drift: the faithful rate moves at HOUR scale on frozen configuration. Measured: 0/32 across 2026-08-02/03 (every child DOA); 45/69 = 65.2% aggregate inside the 2026-08-04 14:53→23:14 window, with an 84.2% sub-window (16/19); 1/9 on 2026-08-05; ~50% → ~90% across 100 minutes on 2026-08-06 with nothing changed; then 10/10 faithful across ~13 hours from 2026-08-06 23:07 to 2026-08-07 11:16. EVIDENCE SHAPE: per-era stamp tallies re-derived from the full transcript record. CONSEQUENCE: NO rate quoted anywhere is a property of a configuration — it is a property of a configuration AND an hour.
TRIGGER.tool-grant: a restart-gated single-variable grid isolated one request-side discriminator. Nine scratch agents, identical minimal bodies, each carrying the same rank-3 pin and launched with no model argument so the pin governs; all nine resolved as intended at layer 2. Against a `Read, Grep` base: the base itself faithful 2/2 · `+Bash` 2/2 · `+WebFetch, WebSearch` 2/2 · `+Agent` 2/2 (the prime suspect exonerated) · `+Skill` SUBSTITUTED 3/3, every stamp. A body-pad bisection at a faithful five-tool grant (~69k/75k/81k/87k initial requests) stayed faithful 4/4, exonerating initial request SIZE to ~87k for that shape, and a separate run whose context grew to ~146k mid-run stayed faithful 11/11, so post-start growth is free. EVIDENCE SHAPE: single-variable cells, one grant changed at a time, restart-gated so each agent type enters the roster cleanly.
GRADE.trigger: the Skill grant is measured SUFFICIENT (n=3) to flip a correctly-resolved request. It is NOT claimed NECESSARY — one counterexample was substituted at ~94k initial size with no Skill grant and with three grants each measured faithful, leaving a possible size-like condition above ~90k and the 87k–94k band unprobed.
LIMIT.regime-conditioned-trigger: the tool-grant discriminator is itself CONDITIONED on the regime, not absolute. In the 2026-08-06/07 faithful window a ×2 control on the very `Read, Grep, Skill` shape that had substituted in EVERY prior era served faithfully — the discriminator did not discriminate at all in that window. Treat it as the best request-side bet available, never as a rule the serving side is obliged to honor.
ANOMALY.reversion: one child served faithfully ×3, then the substituted model ×167, then faithfully again for its final ×2. EVIDENCE SHAPE: one continuous per-turn stamp sequence. CONSEQUENCE: the swap boundary is not always terminal, so a verdict taken from row 1 alone — or from the last row alone — can be wrong in either direction. Audit every turn.
REFUSAL.benign-prompt: a separate false-positive class blocks the obvious workaround. Headless sessions whose MAIN model is `claude-fable-5` were REFUSED at turn 1 under a biology-hazard category on a benign kickoff (instruct one subagent to read eight local project files and report line counts) — three times, across fresh sessions, reworded text, and a front-door file six times smaller, with no biological content anywhere in the prompt or project context. The same kickoff under a different main model runs clean. CONSEQUENCE: routing the work through the never-substituted MAIN path in headless sessions is blocked by this class.
DODGE.file-pointer: the refusal is prompt-surface-shaped and clears with a FILE-POINTER kickoff — `claude -p "Execute the instructions in the file <path>"` ran clean (main served `claude-fable-5` ×36, its executor child ×13, both faithful) where the identical instructions inline refused 3/3. The classifier fires on the inline wording, not the semantics; moving the same text behind a file reference restores the route.
CORROBORATION.metering: in the primary investigation session — which requested `claude-fable-5` for the main loop and for virtually every child — the session's usage-by-model table showed `claude-opus-5` carrying MORE output tokens than fable itself (4.1M vs 2.9M out). EVIDENCE SHAPE: the account's own metering face, independent of every transcript. CONSEQUENCE: the substitution is visible in billing, so a substitution window shows up as the substituted model's token line carrying work you never routed to it, and the crossover when a regime turns faithful is the signature.
SWEEP.client-side-null: the client-side configuration space was swept and came back empty. Rank-1 environment force (including the `[1m]` form), rank-1 unset, rank-2 alias parameter, rank-3 pins in full-id / alias / `[1m]` forms, rank-4 inherit, the default-model alias remap, and effort level max versus high — per-arm n=2 in one evening's regime; no arm moved fidelity beyond regime noise. Sub-findings: the `[1m]` request form is UNREACHABLE for a child (it normalizes to the plain id at rank 1, at rank 3, and through the remap; only the main-loop picker carries it, and the main loop is the one path never substituted); resolution RANK is EXONERATED (ranks 2, 3 and 4 all served faithfully on restricted-grant agents in the same window).
SWEEP.locations-closed: every local location that could affect resolution was read directly and excluded — managed settings absent, shell startup files carrying no relevant variables, project and local settings never carrying a model key in any commit or dated snapshot, no allowlist / override / fallback keys present, and no hook rewriting the launch input (a direct grep over both hook directories returned zero). CONSEQUENCE: the mechanism is SERVER-SIDE; the settings axis is closed and there is no local defect to fix.

# ─── §3 THE PATCH (six pieces; verification, not prevention) ───────────────
PIECE-1.pinned-restricted-executor: a DEDICATED executor agent whose frontmatter carries the FULL model id ([SUPERSEDED 2026-08-09 — the routes moved into the toolkit's GENERAL payload; what makes the pin safe is the NAMED route, never the directory it shipped from] ~~a project-scoped executor agent~~ — they now ship in `payload/agents/` and byte-identically in `planner-kit/payload/.claude/agents/`, admitted by a NAMED allowlist of exactly three that the build gate enforces, along with a FAIL when an allowlisted route LOSES its pin and a FAIL when the two copies drift; the pin is still the defect on any OTHER agent, for the unchanged reason that a shipped rank-3 pin overrides the launcher's tier choice in every session that installs it) (rank 3, measured governing — 9/9 probe cells resolved from their pins with no launch argument), granted `Read, Edit, Write, Grep, Glob, Bash`, granted NEITHER `Skill` NOR `Agent`, and launched with NO model argument so the pin governs. PRECONDITION: the rank-1 environment variable stays at `inherit` or unset — set to a model id it overrides both the argument and the pin.
  GRANT-RATIONALE.three-tiers (the reason each exclusion exists is a DIFFERENT grade of evidence, and they are kept apart on purpose): (i) MEASURED TRIGGER — `Skill` is excluded because it is the isolated flipper above; (ii) DESIGN CHOICE — `Agent` is excluded by doctrine, not by measurement (it measured faithful 2/2): an executor spawns nothing; (iii) UNTESTED COMPOSITION — each granted tool was measured faithful individually and the five-tool set was measured faithful as a set (4/4), but the six-tool composition was never its own cell, and neither was the size band above ~90k. So the shape is a measured BET, not a guarantee.
  SKILLS-BY-READ-POINTER: an executor without the `Skill` grant reaches skill content by READ-POINTER — the brief names the skill file and the child reads it itself, which also satisfies the standing self-service read rule.
  GRADE: `fixture-measured` — a five-launch acceptance passed with every assistant turn of all five runs stamped as requested. REAL-WORLD QUALIFIER: the route REDUCES substitution, it does not ELIMINATE it; the running tally recorded substituted runs on this shape, including one substituted from row 1. Audit every stamp.
  SIBLING-ROUTE.sub-planner (the THIRD certified route, and the only one that can launch children): the SAME construction with exactly ONE more grant — `Agent` — carried by a SUB-PLANNER ([SUPERSEDED 2026-08-09 — same move as PIECE-1: it ships in the general payload now] ~~a project-scoped SUB-PLANNER~~) that runs a full plan → brief → launch → collect cycle inside ONE sealed chunk and returns a compressed roll-up. The extra grant rests on two different things at once: `Agent` was MEASURED faithful individually in the grid above (2/2, where it had been the prime suspect and was exonerated), and a sub-planner that cannot launch children is not a sub-planner. `Skill` stays excluded for exactly the reason it is excluded above. Nesting is ONE level deep — its children are workers, never a third tier — its launches are PARAMLESS so the rank-3 pin governs, and the shared ledgers remain ONE-WRITER, the top coordinator's, so a sealed sub-planner REPORTS what belongs in them instead of writing the row.
  GRADE: `fixture-measured (acceptance REPLICATED ×2, regime-caveated` — three warmup-shaped probes of 7 to 8 assistant turns each, all stamped as requested, plus TWO INDEPENDENT full cycles of 62 and 57 turns with ZERO swaps, each of which planned its chunk, wrote and persisted its worker briefs, launched three lower-tier workers through the `Agent` grant, collected them, spot-checked their receipts against the sources, and rolled up compressed; the workers' own turns all stamped their requested tier, and the pointed persona and skill files were verifiably NAMED AND APPLIED in the workers' artifacts, checked two independent ways. What this certifies is the ROUTING and the coordination SHAPE, not task quality, and it certifies them in the regime they ran in — the same bar the executor route shipped on.
  RELAY-FALLBACK (the route for regimes where the `Agent`-granted shape cannot be certified): the SAME charter runs on the PURE-RESTRICTED executor and the LAUNCHING is relayed, so this path needs no `Agent` grant at all and therefore survives any regime in which a restricted child survives. (1) the restricted child PLANS AND WRITES BUT DOES NOT LAUNCH — every worker brief persisted, plus a launch manifest carrying one row per launch: the agent type, a prompt that POINTS at the brief file rather than restating it, the wave order, and an optional model and description — then it STOPS and reports the manifest ready. (2) the coordinator RELAYS each row VERBATIM, exercising ZERO planning judgment, because judgment added at the relay silently re-plans the very chunk the seal existed to isolate. (3) each returned report is written to the named collect directory and the child is RESUMED by message. (4) the resumed child runs the same collect discipline and returns the same roll-up. What the relay moves is the LAUNCH KEYSTROKE — never the planning, the collect judgment, or the roll-up. MEASURED: one full round-trip, 36 turns all stamped as requested across the planning phase and the post-resume roll-up.
  ROSTER NOTE (a precaution corrected into a measurement): the FIRST launch of a newly added agent type failed with a type-not-found error, and then the roster REFRESHED MID-SESSION with no restart and every subsequent launch worked. So "restart the session after adding an agent type" is a SUFFICIENT precaution, not a necessary wait, on the version measured.
PIECE-2.pointer-reads-as-warmup: open the brief's task with a few small POINTED READS — the persona file, the skill file — so the transcript crosses the deterministic swap boundary on REAL working context rather than on throwaway calls. The reads that certify the launch are the same reads that start the work, so the certification costs nothing extra.
  GRADE: `measured-working` for the delivery mechanics (8/8 read-proof — each child named and applied the pointed file's framework — with 8/8 served as requested), and 6/6 faithful with 6/6 verified uptake in the composition test across persona-only, skill-only and both arms, of which 4/6 were certified live at call 5 while still mid-task.
PIECE-3.watchdog: a transcript-stamp watchdog reads a child's opening serving stamps and returns a verdict by roughly call 5 — FAITHFUL (exit 0) = certified, continue · SWAPPED@k (exit 1) = relaunch, or proceed knowingly and LOG it · UNDETERMINED (exit 2) = investigate. It runs live against a still-running child (`--watch`) or post-hoc against a finished transcript, and an `--expect` argument generalizes it to any pinned model rather than one id.
  GRADE: `fixture-measured (live instances)` — 8/8 production certifications issued mid-run by call 5 at trivial cost, on top of 7/7 fixture cases and correct out-of-sample verdicts on live transcripts.
PIECE-4.relaunch-economics: because the verdict lands at call ~5, a substituted launch is discarded seconds in rather than after a long run has been spent on the wrong model. At the rates measured during the campaign the pattern cost about ONE TO TWO launches per certified child — and that figure is REGIME-CONDITIONED, so it moves with the rate.
PIECE-5.completion-telemetry-flag: a completion hook compares every certified-route child's SERVING STAMP against the shipped model PROMISE of that route (the fable executor promises `claude-fable-5`; the supervised executor promises `claude-opus-5`) and raises a served-model substitution finding on any disagreement. It is VALUE-gated rather than text-shaped: only a real serving stamp may fire it, because a launch argument or a pin inference is intent, not serving. Generic children carry no promise and stay coordinator-audited. It asks NOTHING of the operator — on a certified route the child either works on the model it was promised or the swap is announced; silence stops being an outcome.
  GRADE: `fixture-measured` — 94/94 guard cases including a red arm proving the pre-build silence; NO real swap has crossed it live yet, because the regime has stayed faithful since it shipped.
PIECE-6.dispatch-gate: a launch-time gate makes the shape structurally unavoidable instead of remembered. When a fable-tier or supervised-tier child is about to launch, it DENIES the launch unless (a) the launch names a readable brief file or opens with the warmup token, (b) the resolved brief carries a role line and either names a persona file or states plainly that no specialist fits, and (c) a fable-tier brief carries the warmup token. The denial returns a structured reason naming the failed check, the missing element and the fix, because the point is a correct relaunch rather than a blocked one. A companion advisory hook prints the ready-to-run certification command when a launch returns, so the next action needs no recall. Its trigger vocabulary covers all THREE certified routes, the sub-planner included from the day that route shipped.
  ADVISORY ARM: the same gate also carries a NEVER-DENYING advisory on its PASS path. When a launch requests the ceiling tier BY MODEL ARGUMENT from a GENERIC agent type — any type outside the pinned set — it injects ONE note naming the certified routes (the executor for executor work, the sub-planner for sub-planning) and asking for watchdog certification, and the launch proceeds regardless. That shape is precisely the substitution-prone class measured at §2: a ceiling request from a full-tools agent type. It is an ADVISORY rather than a check because the shape is LEGAL, sometimes necessary, and produced by a server-side defect this gate does not own — so refusing it would be wrong more often than right, while leaving it unnamed is how the measured class keeps being launched by a session that never read this document.
  GRADE for the advisory arm: `fixture-measured (incl. live instances)` — 88 guard cases including a red arm, plus live firing in a real session where the gate denied a coordinator's own non-compliant probe launches and admitted both the corrected ones and a briefed run.
  GRADE: `fixture-measured (live instances)` — a briefless launch DENIED in a real fresh session with the denial text captured, 66/66 guard cases, and the pre-build silent pass printed as the red arm.
CAVEAT.standing (carry it with every number above): rates here are REGIME-CONDITIONED and none of them is a property of a configuration alone; CERTIFICATION-AT-LAUNCH, NOT CONFIGURATION, CARRIES THE GUARANTEE — no settings combination was found that moves child fidelity, while the fidelity itself keeps moving; and a correct REQUEST is not yet the RUN you asked for, so audit the stamps.

# ─── §4 STATUS AND WHAT AN ADOPTER DOES ────────────────────────────────────
STATUS.open: the underlying defect is OPEN and SERVER-SIDE. It has been reported to the vendor with per-request receipts and a runnable reproduction package; the vendor report and the incident record are held privately. Everything in §3 is a measured CONSTRUCTION AROUND the defect, not a fix for it, and it can stop working without notice if the serving side changes.
WATCH.your-stamps: audit the serving stamps of every model-sensitive child at collect. That is the whole discipline — one grep, or the shipped audit instrument, per child that matters.
WATCH.your-metering: check the account's usage-by-model face periodically. A model you never requested carrying your output tokens is the external tell, and it is visible even when no one thought to audit a transcript.
RERUN.after-upgrade: re-run the five-launch acceptance after ANY Claude Code upgrade. This environment's own records show behavior changing WITHIN one version and the version correlation broken at both ends — degradation beginning before a version bump, and opposite outcomes on the same version less than an hour apart — so version stability cannot be assumed.
WHERE.instruments (adopter-relative paths, after installing the toolkit into `~/.claude` and running the kit's own installer in the project root): the project's `.claude/agents/fable-executor.md`, `.claude/agents/fable-subplanner.md` and `.claude/agents/opus5-executor.md` are the THREE certified routes — the ceiling-tier worker, the ceiling-tier COORDINATOR (the one route granted `Agent`, so the only one that can launch children), and the supervised route — and each body carries its own grant rationale, watch conditions and read-pointer mechanics, worth reading before first use · `.claude/skills/model-verification/` holds `fable_watchdog.py` (live and post-hoc certification) and `model_run_audit.py` (the whole-session intent-versus-served audit, with a gate-able exit code) beside its `SKILL.md` · `.claude/hooks/fable-dispatch-gate.sh` is the launch gate and `.claude/hooks/fable-launch-scaffold.sh` the advisory scaffold · the completion telemetry flag rides the subagent completion hook the toolkit installs at `~/.claude/hooks/subagent_qa_gate.sh`.
TIER.doctrine (WHICH work goes to the ceiling at all — the routing question these instruments only answer once it is asked): the NORMAL work tier for file and code reading, writing and editing is the SUPERVISED tier or LOWER, with the supervised model reached ONLY through its certified route above. The CEILING is reserved for — and PREFERRED for — the classes where higher-order reasoning or synthesis is ABSOLUTELY CRITICAL to the piece. Three classes illustrate that test without bounding it: the hardest CODING (novel algorithms, subtle concurrency and correctness reasoning, architecture under ambiguity, and the most complicated models, simulations, physics and mathematics) · high-stakes SCIENTIFIC WRITING (proposal and manuscript drafting, high-order synthesis prose) · the FINAL QA/QC VERDICT class. Route those to the ceiling WHENEVER POSSIBLE and through the certified routes — merited AND preferred, not merely permitted — while CHUNKING even those wherever they separate, and tiering the separable pieces DOWN.
  PLANNING DEFAULT, conditional on the MAIN model: WHEN the main session runs BELOW the ceiling ⇒ PLANNING-CLASS work DELEGATES to the sub-planner route wherever the chunk allows it, and the main agent's own job NARROWS to the three things only it can do — SCOPE ADJUDICATION (what is in and out, and whose boundary that is), CONTEXT CURATION (a sealed brief carrying the file POINTERS the sub-planner reads self-service, plus whatever context only this session holds), and RECEIPTS-BASED COLLECT. The sub-planner launch rides verified-launch like any ceiling-tier child. FALLBACK CHAIN, with the collect NAMING which rung carried the work: a certified sub-planner ⇒ relaunch it when the watchdog says SWAPPED ⇒ the RELAY pattern above, for when the planning must stay at the ceiling but the launching cannot ⇒ supervised planning under the executor contract ⇒ main-agent planning. WHY: the reasoning that DECOMPOSES a task is the part that most rewards the ceiling, and it is exactly the part a lower-tier main agent silently keeps for itself.
  GRADE: `attempted-untested` — this is doctrine. Its behavioral efficacy accrues through the adherence time-series described in ASSURANCE_ARCHITECTURE.machine.md, never through its having been written down, and the tier half of it is what that instrument's tier-explicitness dimension measures per session.
