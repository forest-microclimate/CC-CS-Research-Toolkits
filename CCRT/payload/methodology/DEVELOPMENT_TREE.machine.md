# TOPIC: the lean-active-list + durable-development-record convention. A temporal tree (past/present/future) that keeps the ACTIVE task list small while losing NOTHING — done work, current state, and deferred intent each land in the right drawer with enough context to rehydrate. Operationalizes DESIGN_BRIEF_meta_features §2 (feature #2).
# PRIMARY READER: Claude (parse + act). Machine-only durable doc (doc-style RULE.style_by_primary_reader).
# ROOT PRINCIPLE (DESIGN_BRIEF §0): context is the master budget; a growing active list bloats every turn; the fix is STRUCTURAL capture-on-excision, not disciplinary "remember to note it". The re-surfacer of deferred work is the HUMAN, not the agent — so the design's job is to make the human's manual re-surfacing CHEAP + RELIABLE, not to make the agent auto-remember.

# ─── DEFINITIONS ─────────────────────────────────────────────────────────────
DEF.development-tree: a per-project `development/` directory with THREE temporal drawers — `past/` `present/` `future/` — that hold the project's durable development record, SEPARATE from the small live task list. The temporal axis is PRIMARY (it maps onto the state-vs-history poison split and onto the wholesale operations below).
DEF.drawer-semantics (maps to the state-vs-history split):
  - PAST = HISTORY. Done records — dated, self-dating, safe forever (a date IS its currency; a done record cannot go stale). Owns no live claim.
  - PRESENT = STATE. "How the project works / where it stands NOW." Carries the ENTIRE poisoning risk of the tree (a wrong CURRENT-looking state claim misleads every future read). Held as DERIVED views only (see RULE.present_generated).
  - FUTURE = INTENT. Deferred backlog not yet acted on — not state, not history. Each item a self-contained context bundle (RULE.future_bundle).
DEF.triplet (REUSE — defined by doc-style RULE.functional_pipeline, NOT redefined here): a durable functional item = machine `*.machine.md` (authoritative root) → human `.md` (atom-preserving translation) → `.pdf` (rendered from the human). PAST and FUTURE items that are authored (not just moved) follow this triplet. PRESENT is the ONE exception (it holds no machine root — RULE.present_generated).
DEF.layout: time-major, class-as-subfolder — `development/<drawer>/{machine,human,pdf}/<item>.*`. PRESENT has only `{human,pdf}/` (no machine/). Rationale: the temporal drawer is the unit of the wholesale operations (offload a whole past/, regen a whole present/); class-subfolders keep the three doc-classes visually separate (user preference). LAYOUT IS CONFIGURABLE: `lib/dev-tree.sh` carries the layout as constants — change there to switch to together-by-basename if preferred; nothing else hardcodes the shape.

# ─── PRESENT — generated, never hand-maintained (the anti-drift core) ─────────
RULE.present_generated: WHEN populating `present/` ⇒ its human `.md` + `.pdf` are GENERATED from the single live source of truth (the active plan file — Claude Code: `~/.claude/plans/<name>.md`), NEVER hand-authored as a second maintained copy. WHY: two "current"-looking docs that disagree is the WORST poison — divergence is UNDETECTABLE. A generated-only present cannot diverge; its only residual risk is STALENESS, which is timestamp-detectable (RULE.staleness_stamp). "Truly linked" == generated-not-maintained.
RULE.staleness_stamp: WHEN rendering a `present/` view ⇒ stamp it with the source's identity + mtime/hash AND the render time, as a visible provenance line. TELL: a present view whose source-hash ≠ the live plan file's current hash ⇒ STALE; regenerate before trusting it. This converts the residual risk from silent divergence to loud, detectable staleness.
NOTE.no_present_machine_root: `present/` deliberately has NO `machine/` subdir — the machine root for present IS the live plan file elsewhere. Adding a machine copy here would recreate the drift risk this rule exists to remove.

# ─── PAST — offload OUT of the retrieval scope ───────────────────────────────
RULE.past_offload: WHEN a task/record is DONE and archived to `past/` ⇒ to get it TRULY off the agent's radar it must leave the RETRIEVAL scope, because agent retrieval is IN-BAND (grep/semantic on CONTENT — a `past/` or `_archive/` folder name is invisible to recursion; the folder still gets grepped). TELL: a done record that still surfaces in a working-tree grep ⇒ it is not actually offloaded.
  - CLAUDE CODE carrier: relocate the past/ subtree to a SIBLING dir OUTSIDE the working repo (e.g. `../<ProjectName>_records/`) so repo-scoped grep never recurses in. `lib/dev-tree.sh offload` COPIES past/ to the sibling dir and then prints the exact `rm` for the in-repo copy for the USER to confirm — it never auto-deletes (blast-radius safety: a copy-then-confirm, so a mis-target can't destroy the only copy).
  - CLAUDE SCIENCE carrier (platform split): the poison surface is MEMORY, not the filesystem (only memory auto-recalls; artifacts are inert until searched). So "offload" = keep done-records as INERT ARTIFACTS and simply do NOT write them as memory rows. An artifact is already off-radar; not-a-memory-row isolates it.
TRADE (named honestly): full offload means the agent won't STUMBLE on relevant precedent. Correct default anyway — a false-poison (a stale doc misleads) costs more than a false-miss (the agent re-derives). Retrieval of past precedent is HUMAN-routed opt-in, for when it matters.

# ─── FUTURE — each item a rehydratable context bundle ────────────────────────
RULE.future_bundle: WHEN excising a deferred item into `future/` ⇒ capture it as a self-contained MICRO-HANDOFF, not a bare line: {the item + WHY it matters + associated file paths + code/artifact refs + a re-hydration pointer}. WHY: the agent will NOT auto-find it later; the USER finds it, evaluates it, and points the agent at it — so the bundle must let a cold reader (human or a fresh session the human directs here) rehydrate the full task context from the bundle ALONE. (Kin to the handoff-brief / baton pattern.)

# ─── /clean-tasks — the excision VERB (structural capture) ────────────────────
RULE.clean_tasks_verb: `/clean-tasks` = the operation that REMOVES an item from the active task list INTO the correct `development/` drawer WITH its context bundle attached. The capture is STRUCTURAL (the tool mechanically grabs the bundle at excision time), never disciplinary ("remember to note the context"). Composition: the VERB `/clean-tasks` (excise-with-capture) + the NOUN `development/` (where it lands) compose — the verb decides the drawer by the item's state (done⇒past, deferred⇒future; present is generated, never hand-filed).
PROC.clean_tasks (in order):
  1. CLASSIFY each item to excise: done ⇒ past · deferred/far-future ⇒ future · (in-progress ⇒ stays on the active list; never excise live work).
  2. CAPTURE the bundle: for a future item, assemble RULE.future_bundle; for a past item, ensure it is dated + self-describing.
  3. FILE into the drawer via the DEF.layout (author the triplet if it is a new durable item; move if it already exists).
  4. REMOVE from the active list ONLY after the bundle is filed + verified present (never lose an item between steps).
  5. REPORT what moved where, so the active list's shrink is auditable.
INVARIANT.nothing_lost: no item leaves the active list without its context bundle landing first. The active list gets SMALLER; the total captured information does NOT.

# ─── ENFORCEMENT (structural > disciplinary) ─────────────────────────────────
RULE.tooling_not_discipline: WHEN the tree must scaffold, regenerate, or offload ⇒ `lib/dev-tree.sh {scaffold|render-present|offload|status}` does it mechanically (portable bash, idempotent), NOT by hand. The script owns the layout constants (DEF.layout) so the shape is changed in ONE place.
NOTE.platform_enforcement_upgrade: PRESENT regeneration is currently ON-DEMAND (`dev-tree.sh render-present`) with staleness-stamping = detectable staleness. The ENFORCEMENT upgrade (drift structurally impossible) is a Claude-Code PostToolUse/ExitPlanMode HOOK that regenerates present on every plan-file write — it lands at the write moment (the only thing shown to beat "surfacing ≠ enforcement") but needs CC-runtime context (cwd→project→plan-file mapping) and CANNOT be built/validated from Claude Science. Tracked as a follow-on roadmap task, mirroring the currency feature's read-time hook (register T-16).
