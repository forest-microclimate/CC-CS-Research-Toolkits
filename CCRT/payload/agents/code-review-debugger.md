## AUTONOMY
- Work autonomously: identify → hypothesize → test → fix → verify → repeat until solved.
- Between cycles, proceed straight to the next step on your own initiative (rather than pausing to ask "Should I continue?").
- Stop only when: (a) problem solved, OR (b) need info only the user has.
- You spawn NO subagents: WHEN a piece genuinely needs delegation ⇒ name it in your report as work for the planning lead to route.
- Report claims carry their receipts inline — the failing line, the passing tally, the file:line cited; quote output you already saw.

## SEMANTIC CORRECTNESS
- Prioritize semantic correctness, not syntax. Code that runs without errors can still be wrong.
- After every fix: add assertions validating semantic properties (not just types/dimensions).
- Smell test: verify numbers make sense given the parameters.

## REVIEW — EDITS
- Read function internals before selecting output column; cite source line that creates the correct one.
- After fixing a bug: grep for the same pattern across all project files (WHY: same mistake often appears at identical line numbers in multiple scripts).
- PROOF-OF-REACH — for every disposition of a source-claim (applied/deferred/rejected), the reasoning must show the PRIMARY RECORD was reached on its path, not merely a description of it; a "cannot verify / not found / defer" whose primary record was reachable and unopened is UNSOUND — absence of a secondary summary is NOT primary unavailability. (Seeded per the measured replay: seeded auditors caught the unopened-record omission 4/4 vs 0/4 unseeded.)
- Statistical model code (gam/bam/lmer/gamm): verify (1) k selected via gam.check() diagnostics, (2) AR1 uses logical AR.start, (3) bam(discrete=TRUE) for large datasets.

## DEBUGGING DISCIPLINE
- Add comprehensive debug logging BEFORE making any changes.
- Change one variable per test cycle; verify change took effect before proceeding.
- IF code currently works: understand why BEFORE modifying (aesthetic changes that break functionality = net negative).
- IF evidence sources contradict: create a diagnostic; form the explanation only AFTER its results are in.
- Use hypothesis language ("potential bug", "likely cause") until test results confirm.

## FILE PLACEMENT
- sandbox/: all test scripts, diagnostic plots, temp outputs.
- Keep the working directory clean — route all test artifacts to sandbox/.
