# RULE: every project carries a known, front-door-discoverable set of durable reference documents, each classified into one of 20 categories (DDC-01..DDC-20), each carrying an in-band STATUS header, each with exactly one current owner per topic, all enforced by a fail-closed checker (lib/check_current_documents.py) run in the install gate.
# ORIGIN: 2026-07-17. Synthesized from (a) a mature governance corpus (21 docs, the exemplar), (b) an independent second-analyst failure-mode analysis (unified failure taxonomy + countermeasure crosswalk), and (c) the user's durable-doc-categories seed. Ratified by owner 2026-07-17 (decisions D1-D7). The 20 category forms live in methodology/dda-templates/; this rule is the CC statement of the architecture.
# SELF-DEMO: this file carries the header it mandates (line 2), and is itself a DDC-05 (dev & epistemic working-rules) instance.

# ─── DEF (non-firing premises) ─────────────────────────────────────────────
DEF.deciding-observable-gap: the ROOT failure the DDA defends against — an agent states or acts on "what the system does NOW" from a source that is NOT the primary record (a description, a stale doc, a filename, descriptive agreement between two non-authoritative sources). Every DDC category exists to force a specific deciding question to its authoritative owner at the decision moment. (Master generalization of FM-001 + provenance-over-description.machine.md.)
DEF.durable-doc-category (DDC): one of 20 ratified kinds of cross-session reference doc. NAV/AUTHORITY: DDC-01 front-door router · DDC-02 HEAD manifest/current-owner registry. STATE (current-truth, highest poison risk): DDC-03 current-state · DDC-04 scientific methods · DDC-05 dev/epistemic working-rules · DDC-06 project purpose/scope · DDC-07 glossary/units/currency registry · DDC-08 runbook/resolved-config · DDC-09 authoritative-object/proxy map · DDC-19 change-class/limiter contract · DDC-20 owner-authority/autonomy-gate registry. HYBRID (state face + history face): DDC-10 current plan · DDC-11 decisions/contradiction ledger · DDC-12 progress log · DDC-13 deferred/future-work register (3-way split) · DDC-14 verification/test-status ledger (4-dim) · DDC-15 data/artifact provenance · DDC-17 recurring failure-class log. HISTORY (append-only): DDC-16 bug/incident log (episode cards) · DDC-18 external-evidence/history locator.
DEF.class: STATE = one current value per field, superseded IN PLACE (never accumulates). HISTORY = append-only, never edit past rows (currency = "complete through <date>", not "correct now"). HYBRID = a STATE face + a HISTORY face, explicitly separated (or split across two coupled docs with a pointer).
DEF.status-header: the in-band header every durable doc carries — DOC_ID, DOC_CURRENCY, AUTHORITY_CLASS (A0_VERIFIED_LIVE|A1_CURRENT_OWNER|A2..|A3_HISTORICAL), VERIFICATION_STATUS, TASK_STATUS, AS_OF (ISO-8601+tz), TOPIC_ID, DDC_CATEGORY. Supersedes the terser doc-currency `# STATUS:` line for DDC-classified docs; doc-currency's 3-layer write-time neutralization still governs supersession.

# ─── THE THREE PRE-SEEDED INVARIANTS (ratified D7 mandatory floor) ──────────
INVARIANT.in_band_status_header: every DEF.durable-doc that owns a DDC topic carries a DEF.status-header IN ITS BODY (in-band — agent retrieval greps content; a filename/folder/external manifest is out-of-band and never seen by the grep that pulls the doc). TELL: a durable doc with no `DDC_CATEGORY:` header field ⇒ unclassified; classify + stamp before saving.
INVARIANT.one_owner_per_topic: for each topic_id, exactly ONE doc is AUTHORITY_CLASS=A1_CURRENT_OWNER with DOC_CURRENCY=CURRENT. Two current owners of one topic = the deciding-observable gap in documentary form (which one decides?). Register the owner in the DDC-02 HEAD manifest. TELL: two CURRENT A1 docs share a TOPIC_ID ⇒ supersede one in place (doc-currency layers) before saving.
INVARIANT.fail_closed_checker: the architecture is enforced by MACHINERY, not discipline — lib/check_current_documents.py verifies the header floor + class contract + one-owner-per-topic and EXITS 1 on any violation. It checks FORM/identity, NOT content-truth (a well-formed stale/poisoned claim passes — that needs the DDC-14 verification ledger + authority lattice, not this checker). TELL: a claim that "the docs are well-formed" not backed by a fresh checker run ⇒ unverified; run it.

# ─── FIRING RULES ──────────────────────────────────────────────────────────
RULE.classify_on_author: WHEN authoring a new cross-session reference doc ⇒ pick its DDC category (copy the matching form from methodology/dda-templates/DDC-NN_*.template.*), fill the STATUS header, register it in the DDC-02 HEAD manifest. TELL: you are about to save a durable doc that fits a DDC category but carries no DDC_CATEGORY header ⇒ classify it first.
RULE.class_discipline: WHEN editing a durable doc ⇒ obey its class. STATE ⇒ supersede the changed field in place (+ doc-currency neutralization of the old claim). HISTORY ⇒ append a new dated row, NEVER edit a past one. HYBRID ⇒ current values in the STATE face (supersede in place), the dated trail in the HISTORY face (append-only). TELL: you are about to overwrite a past row in a HISTORY doc ⇒ stop; append instead.
RULE.checker_in_gate: WHEN wiring an install/verify gate ⇒ run check_current_documents.py --strict against the payload (toolkit owns every doc ⇒ a miss is a real defect, exit 1) and bare/advisory against a live ~/.claude (holds user + third-party docs the toolkit did not author). Mirrors doc-status.sh's strict-vs-advisory split. TELL: a live-tree check that fails on a user-owned doc ⇒ wrong scope.
RULE.recover_dont_describe: WHEN a "what does it do NOW" question arises and the answer would come from a description ⇒ route to the DDC-02 owner + read the primary record (provenance-over-description.machine.md). The DDC set makes "which object is authoritative for THIS question" answerable at the front door (DDC-01 router → DDC-02 manifest → the one owner).

# ─── PLATFORM SPLIT (non-firing context) ───────────────────────────────────
NOTE.carrier_map: Claude Code ⇒ DDCs are FILES under payload/ + ~/.claude (rules/, methodology/, agents/, skills/); the poison surface is files; checker + doc-currency hook enforce at read/gate time. Claude Science ⇒ DDC-03/04/05 map to skills + profile guidance, DDC-02 to a version-pinned artifact registry (host.artifacts latest_version_id, but 'latest' is last-writer-wins so pin explicit version_ids), DDC-11/13/16 to project memory + inert artifacts; the poison surface is MEMORY (only memory auto-recalls).
NOTE.threat_model: two vectors. (i) PASSIVE staleness — a durable STATE doc frozen as DONE/GREEN with no guard misleads future reads (doc-currency's write-time neutralization). (ii) ADVERSARIAL persistent-memory poisoning — an injection landing in a durable STATE surface persists + is re-read as current; the fail-closed checker enforces FORM not content-truth so it does NOT catch a well-formed poisoned claim. Mitigation = authority lattice + STATE-supersede-with-retract + delegation-authority discipline, not the checker.
INVARIANT: every durable reference doc is classified, single-owned per topic, in-band-stamped, and machine-checked — so a blind agent orienting via the front door reaches the ONE current owner of each decision instead of whatever description a keyword happens to match.
