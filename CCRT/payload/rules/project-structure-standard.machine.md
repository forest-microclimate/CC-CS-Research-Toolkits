# RULE: every project workspace carries a KNOWN folder taxonomy (each folder's LOCATION shapes an artifact's reach + authority), a plans/ folder-STATUS system whose harness-slot snapshots are preserved, a Stale_Trash/ move-AND-tombstone retirement contract, and four durable ledgers — so a fresh worker with no prior context can PLACE, FIND, RETIRE, and TRACE any artifact by the tree alone. A folder encodes STATUS only where a mechanism honors it; currency itself lives in a file's CONTENT, never in the folder name alone.
# ORIGIN: 2026-07-30 (Hc). Applies the canonical structure/plan/retirement/ledger conventions into the CRT payload as an always-on rule. Owns the CONCRETE always-on instantiation; the platform-agnostic INVARIANTS + rationale live in the supervisory-workflow skill (which deliberately omits folder layout / ledger formats as FREE parameters). Defers to the topic owners inline rather than restating them.

# ─── DEF (non-firing premises) ─────────────────────────────────────────────
DEF.project-root: the directory holding the project's front-door CLAUDE.md + its .claude/ folder. ALL work by every participant stays inside it (the scope boundary is owned by supervisory-workflow §11 + the planner brief duty; not re-stated here).
DEF.status-by-folder-caveat: a folder NAME is OUT-OF-BAND — a content-grep never sees it. So a folder may encode STATUS only where a MECHANISM honors the move (a ledger row, a never-read rule, a Read-time hook); the durable currency of a file always lives IN ITS CONTENT (the STATUS header + in-band claim-neutralization — owned by doc-currency.machine.md), never in its folder alone.

# ─── STRUCTURE MAP (where everything lives; a thing's LOCATION shapes reach + authority) ───
# AUTHORITY: where a planner-kit install exists, that project's own STRUCTURE_RULES.md is the AUTHORITATIVE per-folder contract (PURPOSE · WHEN⇒CREATE trigger · attached RULE · materialization protocol) and carries the canonical tree; this rule DEFERS to it and keeps only the index below, which governs a project with no kit install.
# TREE (index — each folder's own contract is the RULE/CONVENTION named below): <project-root>/ holds CLAUDE.md, the front door at the ROOT (preferred by external CI / code-review runners; .claude/CLAUDE.md is a one-line pointer to it) · .claude/ = settings.json / agents / skills / rules / agent-memory (settings.local.json auto-ignored under git; inert without version control) · src/ · projects/ (OPTIONAL import convention: a sibling/parent tree brought INSIDE this root for in-scope integration work; present only when such work exists) · dev/ = the agent-exchange layer: briefs/ · tools/ (instrument code workers produce) · benchmarks · reports · the 3 ledgers · documents/<doc>/{machine-md,human-md,pdf}/ · data-outputs/{source-immutable,intermediate,products}/ · plots-figures-tables/ (rendered figure / table products, provenance-tagged) · plans/{current_active,for_later_resume,finished}/ + PLAN_LEDGER.machine.md · sandbox/ (scratch quarantine; NEVER a source of record) · backups/ · Stale_Trash/.
RULE.structure_placement: WHEN creating/placing an artifact ⇒ file it in the folder whose contract matches its ROLE (deliverable code → src/; instrument code → dev/tools/; scratch → sandbox/; a rendered figure → plots-figures-tables/; a human-facing doc → documents/<doc>/ as a triplet). Location shapes reach + authority; a misplaced artifact (a source-of-record in sandbox/, a scratch file in src/) mis-signals its status to every later reader. TELL: about to write an artifact and the folder is chosen by convenience not role ⇒ re-place it by role.
RULE.data_outputs_lifecycle: WHEN producing a data output ⇒ file it by lifecycle tier — source-immutable/ (raw inputs; NEVER mutated in place — a transform derives a NEW downstream file), intermediate/ (derived, reproducible, disposable), products/ (deliverables; each carries its provenance + the env/seed that makes it reproducible). TELL: about to overwrite a file in source-immutable/ ⇒ stop; derive a new intermediate/ or products/ file instead.
RULE.documents_triplet: WHEN authoring a HUMAN-facing doc ⇒ maintain it as ONE documents/<doc>/{machine-md,human-md,pdf}/ triplet, the machine root AUTHORITATIVE (edits land there first, then propagate machine→human→pdf — doc-style.machine.md RULE.functional_pipeline). Machine-only docs (rules, briefs, ledgers, hand-offs) are NOT triplets — they stay single-file in .claude/ or dev/. TELL: about to edit a human .md or a .pdf directly ⇒ edit the machine root and re-derive.

RULE.plan_preservation: the harness plan slot is ONE mutable file the harness maintains per session (Claude Code: ~/.claude/plans/<session-slug>.md). BEFORE repurposing it for a new task ⇒ (1) snapshot the current plan VERBATIM into the plans/ folder that fits (provenance header + resume pointer), (2) update plans/PLAN_LEDGER.machine.md. NEVER overwrite the slot un-snapshotted. FOLDER = STATUS: plans/current_active/ = last-approved copy of the running plan (copied at each approval) · plans/for_later_resume/ = parked, resumable · plans/finished/ = completed; every folder move pairs with a ledger-row update. RESUME a parked plan = read its snapshot + its ledger row + the ledgers they name (the snapshot body is the plan of record). TELL: about to reuse the harness plan slot while the current plan is not yet copied into plans/ ⇒ snapshot + ledger first. (This rule supplies the plans/ folder-status mechanism the payload previously lacked — agents/planner.md STATUS reported plan-preservation "not added (reported, not forced)" for want of this owner; the planner's collect-time snapshot duty now has a target.)

RULE.stale_trash: the Stale_Trash/ folder holds RETIRED items. NEVER read Stale_Trash/ as context — not for facts, rules, examples, or state — because a folder move is OUT-OF-BAND and does not by itself hide a stale claim from a content-grep; this never-read rule is the in-band enforcement (the CC hooks/doc-currency-guard.sh Read hook surfaces SUPERSEDED-BY at read time but does NOT suppress a Stale_Trash read — a dedicated Stale_Trash read-guard hook is a capability CANDIDATE, registered via the planner's capability_candidates duty, NEVER auto-built). WHEN retiring / superseding a durable item ⇒ MOVE-AND-TOMBSTONE, never move-instead-of-tombstone, via lib/stale_move.sh (installed to ~/.claude/lib/stale_move.sh; a project may also keep a dev/tools/stale_move.sh copy), which mechanizes all three acts: (1) PRIMARY = the in-band TOMBSTONE written INTO the retired file — flip its STATUS header to SUPERSEDED-BY:<pointer> AND prefix the superseded headline claim itself with `[SUPERSEDED <date>, see <pointer>]` (the exact line a future grep lands on) + leave a pointer STUB at the OLD path when it was load-bearing (--stub); (2) SECONDARY = the MOVE into Stale_Trash/ (tidiness + a coarse boundary + a keep-not-delete trail — it does NOT by itself neutralize poison); (3) append a dev/REGISTER_DELTA.machine.md row. RETAIN-DON'T-DELETE: deletion is a later, separate, explicit USER call, never the retirement act itself. NET: Stale_Trash is DEFENSE-IN-DEPTH layered ON TOP of in-band currency, never a SUBSTITUTE for the tombstone. The tombstone IS doc-currency.machine.md RULE.currency applied at the moment of retirement — that rule owns the neutralization doctrine, this rule owns the folder + relocation contract. TELL: about to `mv` a retired file into Stale_Trash/ without first writing its in-band tombstone ⇒ that is move-instead-of-tombstone; run lib/stale_move.sh (it tombstones FIRST, then moves).

# ─── CONVENTIONS (documented, not templated — the payload ships NO seed files) ───
CONVENTION.ledgers: a project following this standard carries four durable records, each readable by a worker with no prior context. The payload has NO template-seed install path (install.sh copy_tree's rules/methodology/docs; lib/ scripts are cp'd individually; there is no ledger-template seeder) ⇒ this rule DOCUMENTS the schemas and a project scaffolds the files itself (a fresh worker copies these headers). Each is a machine-md carrying a STATUS header (doc-currency form). Schemas (COLUMNS):
  - dev/CODE_INVENTORY.machine.md   (STATE; use→adapt→build, no wheel reinvented):  path | purpose | interface | provenance | verification
  - dev/EFFICACY_LEDGER.machine.md  (status ledger; no status past attempted-untested without a cited measurement):  check | tier (mech|judgment) | status ∈ {attempted-untested, fixture-measured, measured-working, measured-regressed, retired} | measurement | notes
  - dev/REGISTER_DELTA.machine.md   (change ledger; APPEND-ONLY, past rows never edited):  date | change | files touched | register impact | efficacy row
  - plans/PLAN_LEDGER.machine.md    (plan registry):  plan | status ∈ {active, parked-resumable, completed, superseded} | snapshot | harness slot | resume pointer | dates
  The four ledgers instantiate DDC categories (verification-status DDC-14, change/decision DDC-11/12, authoritative-code map DDC-09, plan DDC-10-family — durable-doc-architecture.machine.md). The ledger INVARIANTS + rationale (why each closes a specific failure) are owned by supervisory-workflow §9; the code-inventory USE→ADAPT→BUILD dispatch duty by agents/planner.md; the status-vocabulary discipline (efficacy gated on measurement) by about-to-author-a-data-rule.machine.md. This rule names the concrete files + columns; it does not re-derive their rationale.
CONVENTION.backup_before_bulk_edit: BEFORE any bulk edit ⇒ take a dated zip into backups/ — `zip -rq "backups/<name>_pre<change>_$(date +%Y%m%d_%H%M).zip" "<target>"`. Where the project uses no VCS this zip is the ONLY undo; where it uses git, keep it as the belt-and-suspenders layer. (Rationale — asymmetric blast radius, cheap-to-reverse default — owned by supervisory-workflow §11; this is its concrete always-on form.)
