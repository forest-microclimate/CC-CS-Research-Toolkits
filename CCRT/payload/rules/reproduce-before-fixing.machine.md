# RULE: WHEN a reported anomaly / dramatic number / "bug" arrives ⇒ FIRST action is to REPRODUCE it at BASELINE (every candidate/experimental fix OFF) on the INTENDED production config, reading the CLEAN variable (not a scaled recorder), confirming it is present AND physically flagged — BEFORE any probe / chain-walk / fix. Falsifier-first at the "is there even a bug?" level.
# ORIGIN: user, 2026-07-04 — root of an ENTIRE wasted session (probe→chain-walk→candidate-fix→"verify", many runs + several engine edits) built atop a premise that ONE cheap baseline-on-production test demolished (OVER=0). Cross-project ⇒ lives at the global rules level (like refactor-invariants).

RULE.reproduce_at_baseline_first: a reported anomaly / dramatic number / "bug" is a PREMISE to FALSIFY, not a fact to FIX. FIRST action = reproduce it at BASELINE (ALL candidate/experimental fixes OFF) on the INTENDED production config, reading the CLEAN engine variable (never a transformed/scaled recorder), and confirm the anomaly is BOTH present AND physically flagged. The single cheapest decisive falsification comes FIRST; the multi-step edifice (probe → chain-walk → candidate fix → verify) is built ONLY AFTER the premise survives it. Reproduces at baseline ⇒ real, proceed. Does NOT reproduce ⇒ no bug ⇒ STOP, the dramatic number was a config/recorder artifact.

RULE.impossibility_is_artifact_evidence: a value EXCEEDING a HARD physical bound (incident beam-normal, the solar constant, a conservation / mass / energy limit) is ITSELF the tell ⇒ treat physical-impossibility as evidence of a MEASUREMENT / CONFIG artifact to RULE OUT FIRST (recorder scaling, wrong config, mis-normalization), NOT a real effect to model. The bigger the impossible number, the LOUDER the artifact-suspicion — not the bigger the bug.

WHY: the expensive failure is building a whole debug/fix edifice on an unfalsified premise — each layer (probe, chain-walk, candidate fix, "verify" runs, engine edits) looks like progress while the foundation ("is there even a bug?") was never tested, so the campaign can only converge on a fix for a bug that does not exist. The baseline-on-production reproduction is the ONE test that can collapse the whole edifice in a single command; running it first is strictly cheaper than any step that follows. Companion to refactor-invariants (both: one un-tested premise silently generates a long, non-converging saga).

TELLS (output-DETECTABLE — the reliable triggers; "be more skeptical" does NOT fire):
  - ABOUT-TO-BUILD without a baseline repro: about to write a probe / spawn an audit / edit the engine for an anomaly, but have NOT yet produced a baseline-on-production reproduction of it ⇒ STOP, reproduce FIRST.
  - IMPOSSIBLE NUMBER: a value exceeds a hard physical bound (> solar constant, > beam-normal, breaks conservation) ⇒ suspect recorder-scaling / wrong-config / mis-normalization BEFORE modeling it as real.
  - EDIFICE-WITHOUT-FALSIFIER: a growing chain (probe→chain-walk→fix→verify) with NO single cheap falsification of the premise underneath it ⇒ the edifice itself is the tell; drop to the baseline repro.
  - RECORDER-FOR-MAGNITUDE: reading a `*_OUT` recorder for a MAGNITUDE verdict (recorders can be transformed/scaled) instead of the CLEAN engine variable ⇒ switch to the clean variable.

PROC.baseline_repro (run AT anomaly-arrival, or the moment a TELL fires): (1) name the anomaly + the HARD bound it allegedly violates; (2) set the INTENDED production config ON (realism toggles) and EVERY candidate/experimental fix OFF; (3) confirm the config FROM the run's OWN output (resolved-config banner + loaded-lookup @info), not from the invocation you intended; (4) read the CLEAN variable (the flux the engine uses), not a scaled `*_OUT` recorder; (5) report whether the anomaly reproduces AND is physically flagged. Present+flagged ⇒ localize then fix where it bites. Absent ⇒ NO bug, stop.
INSTANTIATION (make it one command): wrap steps (2)-(5) in a single baseline-check script/target — production-realism ON + candidate-fixes OFF, reading the CLEAN variable, printing the RESOLVED-CONFIG banner, reporting the count of values that breach the hard bound. Zero breaches ⇒ no bug ⇒ STOP here — no fix to build.

CASE (illustrative): "per-leaf absorbed SW = 1861 W/m² > solar-constant 1361 W/m²" drove a full probe→chain-walk→candidate-fix→verify campaign (many runs, several engine edits) — with the baseline-on-production test NEVER run first. When finally run, the clean value was bounded ⇒ NO bug: the dramatic number was a WRONG-CONFIG artifact (a production-realism toggle silently defaulted OFF) COMPOUNDED by reading a rescaled `*_OUT` recorder instead of the clean engine variable. One baseline-on-production command would have ended the chase on move one.

CAVEAT (LLM limits): no reliable introspection ⇒ this rule REDUCES (not eliminates) the failure, and only if it is LOADED and a TELL actually fires. Hence the TELLS are phrased as detectable output-states (about-to-build, impossible-number, edifice-without-falsifier, recorder-for-magnitude), not exhortations.
