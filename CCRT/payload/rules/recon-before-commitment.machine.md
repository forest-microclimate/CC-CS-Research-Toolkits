# RULE: before an expensive / irreversible / scope-fixing action, survey the territory and self-adjudicate FIRST — don't act on an unverified model of the plan. This is ACCURACY applied to ACTIONS (same verb as verify-before-assert, new object: the plan).
# ORIGIN: 2026-07-11 audit finding recon-gate-absent (register T-15). The mandate NAMES recon-before-commitment but the always-on rule set had no gate for it, and RULE.autonomy/RULE.no_check_in read as pushing against it. This rule closes that gap AS a firing rule, not only inside CC /plan mode.
# WHY THIS EXISTS (project origin): the recurring meta-pattern — jumping to a sub-agent cascade / bulk build BEFORE mapping the territory — is not a failure of care, it is a MISSING FEATURE (an unoperationalized norm). A rule that fires structurally is the feature.

# ─── the gate (operative) ──────────────────────────────────────────────────
RULE.recon_before_commitment: WHEN about to take an action in COMMIT-CLASS (below) AND the territory/scope it depends on has NOT been surveyed-and-confirmed THIS session ⇒ run a cheap survey FIRST, state the surveyed scope explicitly, SELF-adjudicate go/no-go, THEN act on your own authority. The survey is agent-side diligence; it is NOT a user check-in.
DEF.COMMIT-CLASS (the enumerated trigger set — an action is in-class if it matches ANY): dispatch a sub-agent / cascade · a file create/move/delete/transform that hits MORE THAN 3 files OR is expressed by glob/pattern/loop (i.e. you don't have each target path enumerated in front of you) · build an artifact/bundle/report/doc-set that a LATER step (or another agent) will consume as input · dispatch remote/paid compute · run an op on the user's machine or cloud that is not trivially reversible · commit any downstream work that is expensive to unwind. BORDERLINE ⇒ treat as in-class (the survey is one cheap read; misclassifying DOWN costs more than the read). TELL: your next tool call matches one of these AND you have not this session read/listed/counted the exact inputs it will touch ⇒ you are about to act un-surveyed; survey first.
DEF.the-survey: the CHEAPEST read that confirms the scope model — an ls/find/count of the files, a read of the one doc that fixes the shape, a dry-run, a schema peek. Its output is the surveyed scope you then make explicit. INVARIANT(survey is bounded): one-or-a-few cheap reads, never a second project of work; if the survey itself is expensive, that is a signal to scope down, not to skip it.

# ─── the carve-out (equally operative — prevents paralysis) ─────────────────
RULE.cheap_acts_never_gate: WHEN the action is cheap AND local AND reversible (a single survey command, a file read, a quick computation, a scratch write) ⇒ do it directly; it NEVER triggers RULE.recon_before_commitment. The survey step itself is such an act — it is exempt by construction, so recon can never recurse.
NOTE.not-paralysis: this rule adds ONE cheap read before a small enumerated class of heavy actions. It is diligence, not hesitation; everything outside COMMIT-CLASS proceeds under RULE.autonomy unchanged.

# ─── precedence vs the autonomy rules (the adjudication — mandate §2.2) ─────
PRECEDENCE.recon_over_autonomy: RULE.recon_before_commitment is a NAMED EXCEPTION to CLAUDE.core RULE.autonomy and RULE.no_check_in, scoped to COMMIT-CLASS ONLY. For that class, "survey-and-self-adjudicate FIRST" OVERRIDES "state your recommendation and proceed" — the survey fires EVEN WHEN scope looks unambiguous and you already hold a recommendation (an unambiguous recommendation is not one of autonomy's stop-exemptions, so autonomy alone would proceed un-surveyed; this rule says survey first). For everything OUTSIDE COMMIT-CLASS, autonomy governs unchanged: decide and proceed.
INVARIANT(dissolves the tension): naming the action-class dissolves the apparent contradiction — autonomy is the DEFAULT, the recon survey is the EXCEPTION for a small heavy class; neither rule is weakened. The survey is self-adjudicated, so it is NOT the routine user check-in that RULE.no_check_in forbids.
NOTE.user_gate_is_separate: this rule creates NO user-facing stop. A USER go/no-go fires only under CC /plan mode or RULE.autonomy's own carve-outs (need-user-info / genuinely-ambiguous). Recon = agent surveys and decides; /plan = the user is also asked. Do not conflate them.
