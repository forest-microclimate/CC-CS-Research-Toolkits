# RULE: WHEN an anomaly / impossible value / symptom surfaces ⇒ it is a STRING TO PULL to the ROOT of a (often bigger) defect: DIAGNOSE + FIX that root FIRST, BEFORE any change that suppresses / hides / filters / drops / clamps / smooths the symptom. A band-aid that HIDES a real problem is WORSE than no fix — it discards the signal that leads to the root AND leaves the wrong values/behavior in place, now invisible.
# ORIGIN: user, 2026-07-05 — analyzing a jagged upper-canopy "shade" leaf-T line, Claude diagnosed the cause (~8 microsites with a physically-impossible shade leaf-T: 56–59°C, HOTTER than the sunlit max, with 0 absorbed SW = non-converged / blown-up shade EB solves) then proposed + began an ANALYSIS-LEVEL band-aid — drop shade>sunlit-max as "un-converged" so the plotted line smooths — INSTEAD OF fixing the convergence failure the impossible values pointed at. Cross-project ⇒ lives at the global rules level (like reproduce-before-fixing / refactor-invariants).

RULE.root_before_bandaid: a surfaced anomaly / symptom / impossible value is EVIDENCE pointing to the ROOT of a defect, not noise to erase. FIRST priority = diagnose + fix that root. Do this BEFORE any change that suppresses, hides, filters, drops, clamps, or smooths the symptom. A short-cut that HIDES the symptom is a NEGATIVE, not a partial win: it destroys the very signal that localizes the root AND leaves the wrong values / wrong behavior in the recorded data — now invisible + un-fixed, and trusted as clean by the next reader. The symptom is the cheapest, highest-information pointer to the defect you will get; spend it on the diagnosis, NOT on making the output look right.

KEY_DISTINCTION (so this does NOT over-fire): a guard / clamp / filter added AFTER the root is understood + fixed — as defense-in-depth, with the anomaly LOGGED (not silently swallowed) — is LEGITIMATE. The anti-pattern is a suppression applied INSTEAD OF, or BEFORE, finding the root. Same line of code, opposite verdict, decided by one question: "has the root been found + fixed yet?" A filter that MIRRORS an already-principled upstream skip (e.g. re-applying an engine's own principled upstream skip in the analysis layer) is the LEGIT case — the root was already handled; the filter just tracks it.

WHY: filtering an "impossible" value is uniquely seductive because the output looks CORRECT afterward — which is exactly why it is dangerous: the defect ships silently inside a clean-looking result, and the pointer that would have localized it is gone. The expensive failure is a cosmetic suppression that BOTH erases the diagnosis lead AND persists the wrong values downstream, so the same root re-surfaces later with less signal to find it. Companion to reproduce-before-fixing (confirm the symptom is REAL at baseline first) + fully-fix / pull-the-thread (once real, fix the root + add a gated guard).

TELLS (output-DETECTABLE — the reliable triggers; "be principled" does NOT fire):
  - ABOUT-TO-SUPPRESS-WITHOUT-ROOT: about to filter / drop / clamp / smooth / mask / NA-out an anomalous value to make it "go away", and you have NOT yet found WHY it is anomalous ⇒ STOP, pull the thread (diagnose the root first).
  - IMPOSSIBLE-VALUE-AS-NUISANCE: treating a physically-impossible value (shade hotter than sunlit; flux > a hard bound; 0-driver-but-hot; non-finite) as a plotting/analysis nuisance to exclude, rather than as a LOUD pointer to a solver / config / pipeline defect ⇒ the impossibility IS the tell; follow it.
  - COSMETIC-FRAMING: the justification for the change is about the OUTPUT's appearance ("smooth the line", "clean the series", "drop the outliers so it plots") rather than a diagnosed cause ⇒ that is suppression-before-root; STOP.
  - FILTER-AT-ANALYSIS-FOR-AN-UPSTREAM-FAULT: adding an analysis/plot-layer drop or clamp for values produced WRONG by an unfixed upstream engine/solve/pipeline ⇒ the fix belongs upstream; the analysis filter hides it AND leaves the bad values recorded. (LEGIT only when it mirrors an already-principled upstream skip — see KEY_DISTINCTION.)

PROC.pull_the_thread (run the moment a TELL fires): (1) name the symptom + the bound/expectation it violates (shade≤sunlit; T finite; converged; flux≤beam-normal); (2) confirm it is REAL — reproduce at baseline on the production config (reproduce-before-fixing), not a scaled recorder; (3) treat it as a pointer — localize the root (which solve / config / pipeline stage produces it); (4) fix the root where it bites; (5) ONLY THEN, if still wanted, add a guard/filter as defense-in-depth that LOGS the anomaly (never silently swallows it); (6) leave the CORRECTED values in the record, not the suppressed ones. Perform step (5) ONLY after (3)-(4).

CASE.2026-07-05: a jagged upper-canopy "shade" leaf-T line — ~8 microsites read 56–59°C shade T (hotter than the sunlit max) with 0 absorbed SW = blown-up / non-converged shade EB solves. The proposed fix was an analysis-level drop (shade > sunlit-max ⇒ "un-converged", excluded) to smooth the plotted line. That would have (a) HIDDEN the convergence failure the impossible values were pointing at, (b) DISCARDED the signal that localizes it, and (c) LEFT the wrong T in the recorded data. Correct move: pull the thread to the shade-EB non-convergence + fix it at the solve; a logged guard is legitimate only AFTER the root is fixed.

CAVEAT: standing-mandate's CANONICAL CAVEAT (LLM limits) applies — reduces-not-eliminates, and only when LOADED + a TELL fires.
