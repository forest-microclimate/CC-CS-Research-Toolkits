# RULE: every durable toolkit doc carries an in-band STATUS header; at supersession the stale doc's BODY is neutralized so no future retrieval reads it as current. Operationalizes standing-mandate §4 (RULE.currency) as an installable convention.
# ORIGIN: 2026-07-11 audit findings status-headers-not-dogfooded + currency-clause-missing (register T-13 + T-14). The toolkit prescribed in-band STATUS headers + write-time anti-poison but carried them on 1/30 of its own docs and had no procedure to re-mark at supersession — this rule closes both by DOGFOODING the mandate on the toolkit itself.
# SELF-DEMO: this file carries the header it mandates (line 2), in the exact form STATUS.form specifies.

# ─── DEF (non-firing premises) ─────────────────────────────────────────────
DEF.durable-doc: a doc meant to be retrieved across sessions — every .claude/ rules/*, agents/*, skills/*/SKILL.md, methodology/*, CLAUDE.md at any level, and any *.machine.md or hand-off/state/plan record. NOT: throwaway scratch, a rendered .pdf (derived), or a *_REPORT authored as a dated one-shot (its date IS its currency).
DEF.status-value: one of exactly three — CURRENT | SUPERSEDED-BY:<pointer> | HISTORICAL. CURRENT = the canonical live doc for its topic. SUPERSEDED-BY:<pointer> = a newer doc owns the topic; <pointer> names it (filename or artifact/version id). HISTORICAL = kept for the trail, owns no live claim (closed record, dropped design).
WHY.in-band-only: agent retrieval is IN-BAND (grep / semantic match on CONTENT). A folder name, a filename, an external manifest are OUT-OF-BAND — the grep that pulls the poison never sees them. So currency MUST live in the doc BODY, and defense must cover each read-path (full-read / grep / manifest-first) separately — mandate §4.
FAILMODE.stale-poison: a durable STATE doc frozen as "DONE / GREEN / VALIDATED / PROVEN" with no staleness guard misleads every future session that retrieves it as current (evidence: 19 of 28 measured dev docs carried such claims with no guard). Traceability dates the decision but does NOT neutralize the claim — currency is a distinct property.

# ─── STATUS HEADER CONVENTION (layer a: the full-read defense) ──────────────
RULE.status_header_present: WHEN authoring or first-editing a DEF.durable-doc that lacks a STATUS header ⇒ add one as line 2 (immediately after the `# <name> (machine-optimized; …)` title line), form `# STATUS: <status-value> (<YYYY-MM-DD>). <one-clause note>`. TELL: a durable doc whose first 3 lines contain no `^# STATUS:` ⇒ it is unstamped; add the header before saving.
RULE.status_form: WHEN writing a STATUS header ⇒ use EXACTLY `# STATUS: CURRENT (date).` | `# STATUS: SUPERSEDED-BY:<pointer> (date).` | `# STATUS: HISTORICAL (date). <what it was>`. TELL: a STATUS line whose value is not one of the three DEF.status-value tokens ⇒ mis-formed; map it to the nearest token. (No "WIP/DRAFT/DONE" here — those are TASK states, they live in the deferred-tasks register, not in a doc's currency header.)
NOTE.one-primary-reader: these headers are COMMENT lines (`#`), not markdown sections — DEF.durable-docs are machine-only (doc-style RULE.functional_pipeline), so the header rides in the machine root and is never rendered to a human PDF.

# ─── WRITE-TIME NEUTRALIZATION (the operative anti-poison fix) ──────────────
RULE.currency (mandate §4, made installable): WHEN a doc/claim is superseded ⇒ at the MOMENT of supersession (you hold full context + control) edit the STALE doc's BODY so any future retrieval pulls its own obsolescence, in THREE layers, one per read-path:
  (a) FULL-READ layer ⇒ flip its STATUS header to `SUPERSEDED-BY:<pointer> (date).`
  (b) GREP layer ⇒ neutralize the superseded CLAIM ITSELF inline — the exact line a grep will hit — by prefixing `[SUPERSEDED <date>, see <pointer>]` to it, so the poisoned sentence carries its own antidote wherever it is matched. This layer is the one most often skipped and the one that actually protects the agent.
  (c) MANIFEST layer ⇒ update the HEAD manifest / index entry to name the canonical-CURRENT doc for the topic.
  TELL: you are about to save a NEW doc that owns a topic an OLDER doc still claims as CURRENT ⇒ you owe all three edits to the old doc in the same change; a new-doc save that leaves the prior doc reading CURRENT is an incomplete supersession.
LAW.neutralize_before_leaving: WHEN you finish superseding ⇒ the OLD doc must fail a "reads as current" check: no CURRENT header, and its headline claim carries the [SUPERSEDED …] prefix. Never rely on a folder move or a header flip ALONE — a grep ignores both.
PRECEDENCE.currency_over_preservation: currency neutralization OUTRANKS "never edit a closed record" — you do NOT delete the old claim (traceability keeps it), you PREFIX it. Editing-to-neutralize and preserving-the-trail are satisfied together by prefixing, never by deletion.

# ─── PLATFORM SPLIT (non-firing context) ───────────────────────────────────
NOTE.platform: Claude Code ⇒ the poison surface is FILES; a PreToolUse hook DOES inject "SUPERSEDED-BY X" at Read time (hooks/doc-currency-guard.sh, T-16 — enforcement at the decision moment via hookSpecificOutput.additionalContext, matcher=Read, always fail-open) and `crt`/doc-status tooling stamps headers. Claude Science ⇒ the poison surface is MEMORY (only memory auto-recalls; artifacts are inert until searched) ⇒ currency = keep ONE per-topic canonical-version memory row + keep done-records as inert artifacts, NOT memory rows.
PRECEDENT.rfc: IETF RFCs use in-band `Obsoletes:/Obsoleted-by:` headers PLUS an index — but their reader is careful; ours greps, so we ADD layer (b) inline claim-neutralization that RFCs don't need.

# ─── ENFORCEMENT (structural > disciplinary — mandate §6) ───────────────────
RULE.machinery_not_memory: WHEN coverage must hold across 30+ docs that drift by hand ⇒ a SCRIPT stamps + checks headers idempotently (lib/doc-status.sh), NOT a hand-maintained list. The script is the source of truth for "which docs lack a header"; run it in the install verify gate. TELL: a claim that "all docs are stamped" not backed by a fresh script run ⇒ unverified; run the checker.
RULE.check_scope_matches_ownership: WHEN the checker runs ⇒ its strictness must match what the toolkit OWNS at that root. Against `payload/` the toolkit authored every durable doc ⇒ `check --strict` (a miss is a real defect, exit 1 — the install GATE). Against a live `~/.claude` the tree ALSO holds the user's own pre-existing skills/agents + third-party docs the toolkit did not author and cannot stamp ⇒ bare `check` is ADVISORY (lists misses, exits 0), so a healthy install never cries wolf. ALWAYS prune `backups/` (installer's own dated snapshots — date IS their currency) + `plugins/` (CC marketplace) — never toolkit currency surface. TELL: a live-tree check that fails on a user-owned doc ⇒ wrong scope; strictness belongs only where ownership is total.
INVARIANT: neutralize poison at WRITE time, in-band, one defense per read-path — never trust a folder name or a header alone; and let the machinery, not discipline, keep coverage current.
