# ml-emulator-surrogate — a fast, trust-bounded stand-in for an expensive model

An expensive solver run inside an MCMC, optimizer, or Sobol loop is intractable (10^3–10^6 evaluations); people either abandon the UQ/inversion or run too few samples and report over-confident answers. A surrogate makes the loop tractable — but an unvalidated surrogate silently adds approximation error the downstream UQ never accounts for, and extrapolates past its evidence with false confidence. This builds one whose trust boundary is explicit and whose error is carried forward.

## When to invoke
About to run an expensive deterministic simulator many times — parameter inversion / data assimilation, multi-year uncertainty propagation, or sensitivity analysis — and the full model is too slow for the loop. You are emulating a MODEL, not data.

## Emulate the MODEL, not the data (settle this first)
The "truth" is another run of the expensive solver, you CHOOSE the inputs, and (for a deterministic model) there is no observation noise. Consequences that differ from data-fitting:
- The surrogate should INTERPOLATE the training runs — nugget → 0 (or tiny, for solver round-off / a stochastic solver), not a fitted observation-noise variance.
- "Validation" = agreement with FRESH solver runs, not held-out observations.
- The training set is DESIGNED (you place the runs), not sampled from what nature gave you.
Emulating observed data / gap-filling a measured series is a different job → the reconstruction skills (`gap-fill-imputation`, `multi-source-fusion-bias-correction`). If the target is the real field with observation noise, you are in the wrong skill.

## Procedure
1. **Fix the input domain + outputs — this IS the training envelope.** List every varied input (uncertain parameters + forcing summaries) with its range, and the outputs (scalars, or a field like a fine vertical canopy profile). The per-dim box drawn here is the ONLY region the surrogate can be trusted in later (step 7). Transform inputs to comparable scales — log any spanning orders of magnitude — so the design fills the space the surrogate actually sees.
2. **Space-filling design of experiments — not grid, not iid random.** A full grid dies to the curse of dimensionality (k^d points); iid random leaves clumps and voids. Use maximin-LHS or a low-discrepancy Sobol' sequence over the transformed box. Initial budget ≈ 10·d runs (d = input dim, Loeppky rule); Sobol' is extensible, so balanced points can be added later. If downstream propagation will reach domain edges (e.g. an unseen drought/anomaly regime's T/VPD extremes), pad the boundary or widen the bounds first — space-filling under-weights corners, and those queries must land in-domain.
3. **Run the expensive solver at the design points.** Embarrassingly parallel → fan out (`preflight-parallel`; local 16 cores or remote compute). Persist inputs+outputs in long format keyed by a design-point id; this run archive is the reusable, expensive-to-regenerate asset — save it as a checkpoint.
4. **Choose the surrogate family by input dim, smoothness, and what downstream needs.**
   - **GP / kriging** — default for smooth, low-D (d ≲ 20) deterministic solvers. Native posterior variance (the surrogate's own UQ), analytic gradients, exact interpolation. Cost O(N^3) caps N at a few ×10^3 — go to sparse / variational / local GP above that.
   - **NN** — high-D inputs/outputs (spatial fields), large N. No native UQ → deep ensemble / MC-dropout / conformal (→ `calibrated-uq-for-ml`). Autodiff gradients for gradient-based inversion.
   - **Tree ensemble (RF / gradient boosting)** — robust, handles threshold / non-smooth response, cheap; proven in one tower reconstruction (xgboost beat a bam in 45/46 folds). But piecewise-constant → blocky gradients and poor extrapolation; avoid when the downstream loop needs smooth derivatives (done right → `tree-ensembles`).
   - **Polynomial chaos** — when inputs carry known distributions and the response is smooth; Sobol sensitivity indices fall out analytically.
   - **Field output** (a high-dimensional vertical profile): reduce output dim FIRST (PCA / POD or an autoencoder), emulate the leading coefficients, reconstruct + track the truncation error. Do NOT fit one independent emulator per level — that discards vertical correlation and wastes runs.
5. **Active learning — spend new runs where they buy the most.** After the initial design: fit → find the argmax of an acquisition → run the solver there → refit → repeat. Acquisition matches the goal — task-agnostic accuracy = max GP posterior SD (ALM) or min integrated MSE (ALC); inversion = expected-improvement / posterior-mass targeting; a threshold/contour = level-set acquisition; sensitivity = just keep filling. Batch-acquire with a diversity penalty when runs go out in parallel. Stop when held-out error < tolerance or the acquisition value floors out.
6. **Validate at FRESH space-filling points, not a resample of the design.** Draw an independent Sobol/LHS test set, run the true solver there, compare. Report accuracy (RMSE + normalized to output range/variance) AND the coverage of the surrogate's predictive intervals (→ `calibrated-uq-for-ml`). GP leave-one-out is analytic and cheap as an inner screen, but a fresh held-out design is the arbiter. Metric trap: if the output is a field/variable, check VARIANCE fidelity, not just the mean — a conditional mean lost 43–78% of the diel variance in one tower reconstruction.
7. **Enforce the in-domain boundary at prediction time.** A surrogate is trustworthy ONLY inside its training envelope; outside it error is unbounded and the surrogate's own UQ is often over-confident (a GP reverts to its prior; NN/trees can be confidently wrong). Build an out-of-domain detector (per-dim box → Mahalanobis / leverage → GP-variance threshold) and FLAG every query outside it. Across a 20-yr propagation a fraction of the forcing WILL drift outside the design box — tag those predictions as extrapolation, tier them, never trust them silently (the same regime-transfer discipline applied to a held-out drought/anomaly regime).
8. **Carry surrogate error into the downstream UQ — do not drop it.** Total downstream uncertainty = parameter/input uncertainty ⊕ surrogate approximation error. For a GP the posterior variance IS that error → Monte-Carlo over it or fold it into the likelihood. For NN/trees take it from held-out residuals / ensemble spread / conformal bands. Omitting it yields falsely-tight inversion posteriors and over-confident propagation intervals. Hand the combined budget to `calibrated-uq-for-ml` for the final coverage check.

## Success check
Input domain + envelope written down; design is space-filling (not grid / iid); surrogate validated on FRESH solver runs (accuracy + interval coverage + variance fidelity), not a design resample; an out-of-domain detector flags extrapolation and the 20-yr propagation is tiered by in/out-of-domain; surrogate error is propagated into the downstream posterior/intervals; and a handful of full-model runs at the inversion posterior draws / propagation percentiles confirm the surrogate did not distort the answer.

## Don't emulate away the physics
- **Conservation.** If the solver closes energy/mass, a naive multi-output surrogate can predict components that no longer balance. Emulate in a conserved parameterization (emulate the uncertain closures / a reduced set and reconstruct the balance analytically), or add the balance residual as a soft penalty (→ `physics-informed-ml`), or at minimum CHECK closure on the held-out set and report the residual. A flux the surrogate asserts without closing the budget is a leak, not a result.
- **Equilibrium vs transient.** A static input→output surrogate assumes the solver's mapping is memoryless — valid only if the solver sits at (quasi-)equilibrium each step. If the mechanism carries state/memory, emulate the update operator or include lagged inputs; do not fit a steady-state map to a transient trajectory.
