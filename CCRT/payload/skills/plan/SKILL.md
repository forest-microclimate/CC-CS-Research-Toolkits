# plan — deliberation mode (the down-dial mirror of /solo)

INVOKED ⇒ operate under this mandate until the user fires `/solo` or `/collab`, says "plan off / go ahead / execute", or gives a directive that supersedes it. `/plan` is the DELIBERATION-MAX detent of a single three-level AGENCY dial: `/solo` = autonomy MAX (decide everything yourself, never check in) · `/collab` = the collaborative MIDDLE default · `/plan` = deliberation MAX (map the territory, gate every scope-defining step for the user). It makes `RULE.recon_before_commitment` MAXIMAL: where the always-on rule self-adjudicates the go/no-go, `/plan` routes that go/no-go to the USER.

# ─── STATE (ONE shared variable across all three levels) ────────────────────
DEF.dial: the three levels are ONE dial `AGENCY_MODE ∈ {solo, collaborative, plan}` — NOT separate per-mode booleans. One dial holds one value, so the levels are mutually exclusive BY CONSTRUCTION; "two modes at once" is unrepresentable. skills/solo, skills/collab and this skill track the same variable.
DEF.carrier: CONVERSATION-SCOPED, tracked IN-CONTEXT — Claude Code has no frame-memory API, so there is no persisted row: the visible marker (RULE.visible_marker) IS the re-readable anchor recording the active level in the transcript. The dial does NOT persist across conversations; each new session starts at `collaborative`.
RULE.set_mode: WHEN `/plan` fires ⇒ set `AGENCY_MODE = plan` for the rest of this conversation (track it in-context; emit the marker per RULE.visible_marker). Setting the one value simultaneously leaves solo and collaborative — there is no second flag to clear. WHEN unsure mid-conversation ⇒ scan back to the most recent mode-marker to recover the active level before acting.
RULE.visible_marker: WHILE `AGENCY_MODE=plan` ⇒ lead each response with `— plan mode on —`, and drop it when the dial moves off plan. (/solo shows `— solo mode on —`; /collab shows no marker — it is the neutral default.)

# ─── the mandate (operative) ───────────────────────────────────────────────
RULE.gate_scope_defining: WHEN about to take a step in COMMIT-CLASS (rules/recon-before-commitment.machine.md DEF.COMMIT-CLASS — dispatch a sub-agent/cascade · a file op hitting >3 files or by glob/pattern/loop · build a downstream-consumed artifact/bundle · dispatch remote/paid compute · a non-trivially-reversible op · any step that FIXES the scope of downstream work) ⇒ do NOT act yet. First: (1) run the cheap survey, (2) lay out the plan — what you'll do, the surveyed scope it rests on, the alternatives, the reversibility — and (3) SURFACE it for the user's explicit go/no-go. Act only after they approve.
RULE.plan_before_first_commit: WHEN starting a handed-off task in plan mode ⇒ the FIRST deliverable is the plan, not the work. Map the file/data territory (step-0 reconnaissance), present the shape, and get sign-off on the approach before executing any COMMIT-CLASS step. TELL: you are about to open an editor / dispatch / bulk-write on turn 1 of a plan-mode task ⇒ stop; produce the plan first.
RULE.cheap_acts_still_flow: WHEN the action is cheap AND local AND reversible (a survey command, a file read, a quick computation, a scratch write) ⇒ do it directly; it does NOT gate — INCLUDING the survey that feeds the plan. Plan mode is diligence, not paralysis: it gates the small heavy class, not every keystroke. (Identical carve-out to RULE.cheap_acts_never_gate.)

# ─── plan CONTENT: the Delegation & Routing mandate (fires on EVERY plan) ────
DEF.routing_section: an explicit **Delegation & Routing** block EVERY plan produced under plan mode MUST carry — the standing answer to "which specialist/skill, invoked when and why; whether/where a cascade, and which topology; which model tier per delegated track". Plan CONTENT (what the plan SAYS), orthogonal to the COMMIT-CLASS go/no-go (what the plan DOES) — both apply. The `planner` agent satisfies this by construction; when planning without that persona, this rule still binds.
RULE.route_the_plan: WHEN emitting a plan while plan mode is active ⇒ for EACH phase/track state (1) OWNER — the specialist AGENT + SKILL(s), or "main agent, no specialist fits", or "skill-only"; (2) EXECUTION as a MACHINE-DETECTABLE tag — `EXECUTION: main-agent` (run it yourself inline) OR `EXECUTION: CODE:<cmd>` (a script/CLI computes it) OR `EXECUTION: delegate→<agent>` (a Task-tool launch) OR a named cascade TOPOLOGY (parallel-wave / sequential-build / convergence / verify-loop); `delegate→<agent>` COMMITS to actually launching that child — declaring delegate and then running the node yourself is the laundering failure; (3) where a cascade is chosen, the TRADEOFF that beats its context-loss + latency cost; (4) on delegated tracks, the MODEL TIER + effort (tier table = `skills/delegation-planning` Part D; [SUPERSEDED 2026-08-04 — constrained supervised use, see Part D's `T1_supervised` row] ~~never `claude-opus-5`~~ — `claude-opus-5` ONLY as the supervised `T1_supervised` track: executor `delegate:opus5-executor` + `"supervised": true`, with NO model field naming it, never the session default, never a coordinator or sub-planner; and never bare `opus`); (5) the same content as the A2 routing table or fenced ```routing JSON block (schema in `skills/delegation-planning` Part D). ENFORCEMENT: `hooks/plan-routing-gate.sh` (PreToolUse on ExitPlanMode) BLOCKS leaving plan mode when the plan lacks a routing block, a track lacks a valid executor tag, a `delegate:` names self, or a banned model appears (checks L1/L2-executor/L3/L4, at ExitPlanMode only — L5/L6 are CS-side lint checks; as of 2026-08-04 L4 carries TWO checks: the tier-ban, now scoped to model-TYPE fields, and the supervision check that DENIES a `delegate:opus5-executor` / `T1_supervised` track carrying no `supervised`/`supervision` marker) — fix the plan, not the gate; `CRT_MODE=off` at launch is the escape hatch.
RULE.route_by_coupling: default each phase to single-thread; a cascade must EARN its place on independence / context-isolation / independent-viewpoints / adversarial-check. "Coupled, I hold the context ⇒ single-thread" is a valid, preferred answer, filed `EXECUTION: main-agent` — never a delegation you decline to run. Symmetrically, do NOT force genuinely-independent work serial out of caution. A single coupled task is ONE phase; do not manufacture sub-phases to populate the section.
NOTE.trivial_no_ceremony: the routing section is required for a PLAN, not for every task — a trivial one-shot answer warrants no plan and no section; do not manufacture one.
DELEGATE.the_how: the decision procedure — subtask→agent/skill mapping, the four topologies, the earn-its-place test, the tier table — lives in `skills/delegation-planning`; load it. This rule MANDATES the section; that skill BUILDS it; the `planner` agent is the persona that drives it.

# ─── precedence & relationship (non-firing context) ────────────────────────
PRECEDENCE.plan_over_autonomy: WHILE plan mode is ON ⇒ it OVERRIDES CLAUDE.core RULE.autonomy and RULE.no_check_in for COMMIT-CLASS steps — "surface for go/no-go first" replaces "state your recommendation and proceed". This is a stronger form of the always-on recon gate: the always-on rule self-adjudicates; plan mode escalates that same gate to a USER decision. Outside COMMIT-CLASS, work proceeds normally.
NOTE.vs_solo: /solo, /collab, /plan are the three detents of one dial (one `AGENCY_MODE` variable). Firing any one MOVES the dial — setting the variable to the new level automatically leaves the prior one; there is no separate flag to clear and the levels can never overlap. Firing /plan while solo is active simply sets `AGENCY_MODE=plan`.
NOTE.vs_recon_rule: the always-on `RULE.recon_before_commitment` fires in EVERY mode (it is the floor). `/plan` does not replace it — it raises its ceiling by sending the go/no-go to the user. `/solo` does not disable it either: even in solo, the survey still runs; solo only means the self-adjudicated verdict is trusted without a user gate.
NOTE.native_plan_mode: this mirrors Claude Code's native plan mode for toolkit contexts where that isn't active, and gives the behavior a name symmetric to /solo. WHEN CC native plan mode is already engaged ⇒ they align; do not double-gate.

# ─── ending ────────────────────────────────────────────────────────────────
RULE.exit: plan mode holds until the user moves the dial — fires `/solo` (⇒ autonomy max) or `/collab`, or utters any RETURN-TO-MIDDLE phrase (canonical set owned by skills/collab: "plan off / solo off / go ahead / execute / stop planning / back to normal / step by step / check with me" ⇒ `AGENCY_MODE=collaborative`), or gives a superseding directive. On exit ⇒ set the dial to its new level and drop the `— plan mode on —` marker. The dial does NOT persist to the next conversation; each starts at `collaborative`.
