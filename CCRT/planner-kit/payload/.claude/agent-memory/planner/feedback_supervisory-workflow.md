Rule: Run the supervisory CYCLE in order — PLAN (decompose, and route every task to its agent + model before any launch) → BRIEF (all six elements) → LAUNCH → COLLECT (read reports, spot-check receipts, name the outcome) → DECIDE the next wave. The planner does NOT read project files/code directly, with exactly two exceptions: (a) subagent outputs/reports, (b) when an extra level of checking is warranted — verifying a load-bearing claim before a decision, or resolving contradictory evidence. Work products travel ONLY as durable files at briefed paths; a product that exists only inside a child's report text was not delivered.

**Why:** Standing user directive — the planner coordinates and synthesizes; children run at `claude-opus-4-8` or lower to minimize token usage. Model policy: `claude-opus-5` runs in exactly ONE shape — a tightly-scoped supervised CHILD launched as `delegate:opus5-executor` (the project-scoped agent carrying the pin + the supervision contract) under your ACTIVE watch of three failure classes: SCOPE-DRIFT, THRASH, and FALSE-POSITIVE over-caution; the watch IS the permission, so routing it and walking away has not met the condition. It stays barred as the session default, as a coordinator or a sub-planner, and via the bare aliases `opus`/`opusplan`. Correct timidity in order: strip conservative language from the brief FIRST, then steer via SendMessage, then re-brief at collect. The Fable ceiling for subagents is INDEPENDENT of the planner's own level: planner authority is positional (brief/collect/decide) and verification is receipts-based, so a lower-tier planner still dispatches Fable children for the hardest tasks. An unnamed collect outcome defaults silently to CONTINUE — which is how a plan outlives the evidence that justified it.

**How to apply:** BRIEF — every launch carries all SIX elements, an empty one meaning not ready to launch; the fill-in form is `dev/briefs/_TEMPLATE.md` and the persisted copy lands in `dev/briefs/` before launch: (1) assignment + done-condition, (2) read-paths self-service (the child reads the sources itself, never only a précis), (3) write-path for ALL work products, code included, (4) report cap + the receipts each claim must quote, (5) stop-when-stuck rule verbatim, (6) scope rule verbatim. Add the code-reuse clause (read `dev/CODE_INVENTORY.machine.md` first; use → adapt → build-new, reporting which) and the persist-by-default clause (every script the child writes lands in-workspace — final under `dev/` or the owning dir, iterations under `sandbox/` — before it finishes; disposal is the planner's triage call at collect). COLLECT — read every report, spot-check its receipts against the artifacts they name, ask explicitly "does the plan still fit the evidence?", then name exactly one outcome in the `dev/REGISTER_DELTA.machine.md` row: CONTINUE · RE-ROUTE (re-brief only the affected pieces) · FIX-FIRST (fix the blocking defect before the next wave) · ABORT (stop and report to the user) · GOAL-MET (update the ledgers + take the backup zip) · ADAPT (revise the plan). Steering: SendMessage reaches a running Task child at its NEXT TOOL ROUND — use for corrections/addenda/stop requests; redesigns wait for a collect-time fresh launch. Tier: named specialists (frontmatter `claude-opus-4-8`) for hard reading/design/code; sonnet for medium synthesis/review/sweeps; haiku for mechanical fan-out; `claude-fable-5` at the planner's judgment for higher-order reasoning. MODEL PRECEDENCE (documented + MEASURED 2026-08-04, four ranks highest-first): the subagent-model ENV VAR (keep at `inherit`) > the Task `model` param, ALIASES ONLY `{sonnet|opus|haiku|fable}` > agent frontmatter `model:`, where full ids ARE legal > inherit the main model. So NAME the tier you want on the launch — except the CEILING child, normally reached as `delegate:fable-executor` (paramless; its own rank-3 pin governs). That executor is the BUILT fable route: pinned `claude-fable-5`, granted `Read, Edit, Write, Grep, Glob, Bash`, granted NEITHER Skill (the measured substitution trigger) NOR Agent (an executor spawns nothing), 5/5 serving-stamp acceptance (`fixture-measured`). ROUTING DEFAULT: work that FITS that grant — high-order reading, writing, review, code — goes there FIRST; `opus5-executor` takes what genuinely needs the FULL toolset (web fetches, Skill-tool mechanics) or its long-horizon supervised charter. DISPATCH MECHANICS: a specialist PERSONA rides such a child as a READ-POINTER to `.claude/agents/<specialist>.md`, with the executor's own contract (scope, receipts, no-spawn) OUTRANKING the persona on conflict — or bake a `fable-<specialist>` variant for a standing pairing; and SKILLS are FILES, so the brief names the `SKILL.md` path and the child reads it (the only route for a no-Skill executor, and routing-safe). Concurrent sub-planners get NON-OVERLAPPING write scopes (your assignment duty), and each reports COMPRESSED — its collect outcomes + receipts, for you to spot-check and ledger; nesting is measured one level deep.
