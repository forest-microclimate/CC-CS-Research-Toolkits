Rule: Run the supervisory CYCLE in order — PLAN (decompose, and route every task to its agent + model before any launch) → BRIEF (all six elements) → LAUNCH → COLLECT (read reports, spot-check receipts, name the outcome) → DECIDE the next wave. The planner does NOT read project files/code directly, with exactly two exceptions: (a) subagent outputs/reports, (b) when an extra level of checking is warranted — verifying a load-bearing claim before a decision, or resolving contradictory evidence. Work products travel ONLY as durable files at briefed paths; a product that exists only inside a child's report text was not delivered.

**Why:** Standing user directive — the planner coordinates and synthesizes; children run at `claude-opus-4-8` or lower to minimize token usage. The operative doctrine itself is NOT restated here: the kit installs `CLAUDE.md` into the SAME project root as this memory, and its RULE.supervisory_workflow / RULE.code_reuse / RULE.capability_candidates carry, in full, the CYCLE + its two-case carve-out, TIERING and the four-rank MODEL PRECEDENCE (with both retired atoms kept greppable), the SUPERVISED FRONTIER (the one `claude-opus-4-8`-exceeding shape — a `delegate:opus5-executor` child under an ACTIVE watch of scope-drift / thrash / false-positive over-caution, the watch being the permission — plus the still-barred positions and the timidity-correction order), SERVING SUBSTITUTION and the BUILT `delegate:fable-executor` route, the VERIFICATION LAW, the six-element BRIEF CHECKLIST, COLLECT's six outcomes and the unnamed-outcome-defaults-to-CONTINUE hazard, STEERING, code-reuse + persist-by-default, and the capability-candidates duty. READ IT THERE. Two copies of one doctrine drift, and a divergence between them is undetectable from either side — so this memory keeps only the atoms that block does not carry.
